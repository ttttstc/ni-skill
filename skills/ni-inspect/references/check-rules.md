# 预检规则与反 AI 检查表

本文是 ni-inspect 的独立检查依据。规则与 ni-writer 吸收的 `human-writing` 语义检查保持一致，但 ni-inspect 不在运行时读取其他 skill。

## 1. 正文基本信息检查

| 检查项 | 阈值 | 不达标级别 |
|---|---|---|
| 标题存在且与核心判断一致 | 有 | BLOCKED |
| 正文长度 | 足以承载已确认大纲 | WARNING |
| 小标题层级 | 清楚、服务论证 | WARNING |
| 排版模块、摘要、图片 | 不作为本 Skill 前置条件 | INFO |

## 2. 内容质量检查

| 检查项 | 标准 | 不达标级别 |
|---|---|---|
| 翻案腔 | 0 处 | BLOCKED |
| 洞察路标、Chatbot 残留和空泛结尾 | 0 处 | BLOCKED |
| 绝对禁用黑话 | 0 处 | BLOCKED |
| 正文破折号和提示性冒号 | 0 处 | BLOCKED |
| 重复标点、引号混用和格式损坏 | 0 处 | BLOCKED |
| 副词 | 可删除项已删；程度和范围有证据 | WARNING |
| 上下文词 | 有明确对象和技术含义 | WARNING |
| 加粗密度 | 任一段加粗字数 ≤ 该段 15% | WARNING |
| 事实与推断 | 来源、亲历、推断、未验证项边界清楚 | WARNING |
| 技术论证 | 核心判断有证据，且有边界、代价或反例 | WARNING |

加粗密度只提示视觉拥挤，不要求文章必须加粗或制造金句。Markdown 标题不额外套粗体。

## 3. 大纲、证据与链接检查

| 检查项 | 阈值 | 不达标级别 |
|---|---|---|
| 核心内容与结构 | 与 `article-outline.md` 一致 | BLOCKED |
| 事实证据 | 每项有来源或实践记录 | BLOCKED |
| 实践声明 | 与 `practice-record.md` 一致 | BLOCKED |
| 成立边界 / 代价 / 反例 | 至少有一项 | WARNING |
| 正文外链 | 只保留影响结论的关键链接 | WARNING |
| 来源链接 | 指向原始来源而不是摘要 | WARNING |

## 4. 翻案腔按动作检查

禁的是先制造读者并没有的误解，再推翻它给下文抬价。常见外衣包括：

- 不是 A，而是 B
- 并非 A，而是 B
- 不在于 A，而在于 B
- 与其说 A，不如说 B
- 表面 A，实际 B
- 你以为 A，其实 B
- 回头才发现
- A 不重要，重要的是 B
- 答案恰恰相反

发现后默认标 WARNING，建议从正面写判断，把依据放到附近。只有翻案句同时制造事实误导、掩盖证据缺口或让核心判断失真时才升级为 BLOCKED。文章确实用材料走过作者的自我修正时，可以保留修正过程，但不能套用这些固定外衣。

## 5. 硬套话与协作残留

以下表达在用于抬高段落、替用户说话或暴露 Chatbot 角色时标 WARNING；严重重复或影响论证时升级为 BLOCKED：

- 说白了、说穿了、先说结论
- 值得注意的是、需要指出的是、不难发现
- 更微妙的是、还有一层、只说对了一半
- 从某种意义上说、让我们来看看、接下来让我们
- 希望对你有帮助、当然！、好问题、您说得对
- 如果需要更多信息、综上所述、不言而喻、毋庸置疑
- 未来可期、星辰大海、道阻且长、未来已来、拥抱变化

逐条定位。不要只报命中词，要说明它是否在当前语境中执行了被禁止的修辞动作。

## 6. 黑话分级

### 绝对禁用

赋能、抓手、商业闭环、价值闭环、能力沉淀、拉通、底层逻辑、顶层设计、认知跃迁、价值释放、能力建设、降本增效、内容矩阵、全链路、组合拳、打开想象空间、结构性机会、关键命题、深层逻辑、技术底座、公共底座、技术主权、单点风险、主脊柱、材料锚点、认知增量、迭代闭环。

命中后优先改成人、组件、动作、时间、钱和后果；技术语境中有明确含义时保留。

### 结合语境检查

沉淀、颗粒度、对齐、协同、链路、生态位、心智、范式、方法论、核心变量、打法、想象空间、闭环、不丢。

它们表示化学沉淀、排版对齐、网络链路、控制回路等明确含义时保留；只是给普通事情抬价时标 WARNING。

## 7. 副词检查

### 优先做删除试验

非常、极其、相当、颇为、尤其、真正、其实、显然、当然、无疑、自然、深度、全面、充分、不断。

删除后事实、时序、程度和语气都不变，标 WARNING 并建议删除。

### 必须有材料支撑

显著、大幅、明显、极大、普遍、通常、往往、始终、从不、全部、持续、长期、短期、快速、稳定。

没有数据、时间范围、比较对象或明确样本，标 WARNING。修复建议要么补证据，要么换成具体变化，要么删除副词。

### 可以自然保留

后来、当时、已经、仍然、只、也、就、还等词确实承担时间、范围或自然语气时保留。不要把减少副词执行成机械清零。

## 8. 标点与格式

- 正文不用中文长破折号 `—`、`——`；按写作规范使用且前后有空格的短横 `–` 可以保留。
- 冒号 `：` 与 `:` 只用于引出人物直接原话。
- URL、代码、命令、配置、机器字段和模块注释不参与冒号检查。
- 中文正文使用「」，不混用直引号和弯引号。
- 重复问号、感叹号和叠句号清零。

检查器必须先排除代码块、行内代码、URL 和模块注释，再判断正文。

## 9. 结构性 AI 味

以下问题结合上下文标 WARNING，严重影响阅读时可升级为 BLOCKED：

- 三项以上同构排比，只为气势凑齐
- 连续多段用同样长度、同样句式和同样位置的短判断收尾
- 新段落只换一种说法重复前文
- “进行、实现、完成、开展”带着动名词，动作被名词化
- 精确时间、天气、神态、房间和原话没有来源，只负责制造现场感
- 多套借喻短距离切换，事实反而消失

真实的技术并列清单不属于同构排比。步骤和分类确实来自材料时可以保留。

## 10. 证据与边界

技术文章检查：

- 核心判断是否挂靠亲历记录、代码、日志、截图、数据、官方资料或可复查案例。
- 是否把单次个案写成普遍规律。
- 是否区分亲历、转述、推断和未验证项。
- 是否说明至少一个成立边界、代价、反例或失败条件。
- 行动建议是否能从前文事实和机制推出。

证据缺口默认标 WARNING。明确虚构、伪造来源或把未验证内容冒充已验证结果时标 BLOCKED。

## 11. 分级总表

| 级别 | 触发项 | readiness 影响 |
|---|---|---|
| **BLOCKED** | 标题缺失或偏离大纲、明确虚构、伪造来源、把未验证内容写成事实、把未实践内容写成亲历、关键判断没有证据 | `blocked` |
| **WARNING** | 翻案腔、硬套话、上下文黑话、结构性 AI 味、链接过多、证据边界不足、标题或结构问题 | 无 BLOCKED 时为 `degraded` |
| **INFO** | 不影响发布的节奏、措辞和结构观察 | 不改变 readiness |

- 有 BLOCKED → `blocked`
- 无 BLOCKED，有 WARNING → `degraded`
- 全部通过 → `ready`

## 12. 检查边界

ni-inspect 只体检、定位和建议，不改文章。每个问题必须指向具体句子，并解释当前语境中的问题。词表全绿只说明没有明显外形问题，不代表文章已有材料、有说话位置或自然推进。
