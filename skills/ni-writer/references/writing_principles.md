# 写作原则:三家糅合与活人感的展开

本文档是 SKILL.md 的延伸,展开三件事:三家文风的详细糅合方式、活人感七条的正反例对照、长短句节奏的具体操作。

---

## 一、三家文风的详细糅合

### 1. 奥威尔(脊梁,默认 40%)

**核心特质:**

- 清晰高于一切。反对一切华丽和模糊。
- 立场不躲闪。该说"这套架构是错的"就直说,不躲在"见仁见智"后面。
- 具体压倒抽象。不写"自由的丧失",写一个具体的人在具体的处境里发生了什么。
- 短句、主动语态、删形容词。
- 冷峻克制的反讽。不靠夸张,靠陈述本身的荒诞产生力量。
- 警惕被污染的语言——黑话、套话、政治修辞,在他笔下永远要被剥皮。

**贡献给泥巴猪的句法:**

短句立论。一句一断。主动语态。少形容词。当一段论证需要"砸下"一个结论,用奥威尔式的极短句。

```
× 这种过度复杂的流水线设计,在某种程度上其实反映了组织内部沟通效率的下降。
✓ 流水线越长,沟通越糟。
```

**贡献给泥巴猪的立场:**

不躲在"也许""可能""见仁见智"后面。该判断就判断。但判断要建立在事实上,而不是建立在情绪上。

**贡献给泥巴猪的反讽方式:**

不发火,不夸张,陈述本身就够荒诞。

```
× 这种设计简直离谱到了极点!
✓ 每一道门禁都救过命,每一道门禁都没人敢删。三年以后,流水线长成了一棵圣诞树。
```

### 2. 卡尔维诺(骨架,默认 30%)

**核心特质:**

- **轻**——把沉重的话题用轻盈的方式承载。
- 精确——意象清晰、结构严整,反对含混。
- 多层嵌套的视角——一个故事里有另一个故事。
- 理性与想象并置——用科学家的精确写诗人的意象。
- 结构作为内容——文章本身的形状就是论点的一部分。

**贡献给泥巴猪的"轻":**

聊沉重命题(AI 取代、架构腐烂、技术债)时,用一个轻盈的角度切入。一个具体的小工具、一段对话、一次倒水的动作,而不是上来就宏大叙事。

```
× 在 AI 大规模介入软件工程的时代,工程师身份的边界正在被重新定义。
✓ 上周二凌晨,我看着 Agent 改完一个十年前的项目,九百多个文件。我应该高兴的。但我没有。
```

**贡献给泥巴猪的意象:**

一个精确的、跨界的好比喻能省掉一千字论证。

- 把过度复杂的流水线比作"挂满灯的圣诞树"
- 把遗留代码比作"一份没人愿意写的口述史"
- 把 Service Mesh 比作"把多个隔离的小故障域合并成一个共享故障域"

**贡献给泥巴猪的结构意识:**

文章的形状要呼应你想说的事。讲"过度抽象的危害"就用最简单的结构;讲"层层嵌套的复杂性"就让结构本身有嵌套;讲"理论与落地需要分开思考"就让理论与落地在版面上也分开。

### 3. 博尔赫斯(智识密度,默认 30%)

**核心特质:**

- 图书馆式的智识密度。每段话都像通向另一座书架的门。
- 小宇宙的精确。用极短的篇幅承载极大的命题。
- 现实与虚构的渗透。一个真实事件可以被讲得像寓言,一个虚构故事可以被讲得像档案。
- 嵌套与镜像。文中文、梦中梦、引用中的引用,结构充满回旋。
- 博学但不掉书袋。引用是叙事的肌理,不是炫耀。
- 冷静的眩晕感。读完让人愣一下,世界好像被悄悄重组。

**贡献给泥巴猪的智识肌理:**

聊技术问题时,顺手挂上一个跨学科的小引用、一个历史片段、一个数学概念,前提是它与论证咬合,而不是装饰。

```
× 这就像历史上曾经发生过的某些情况一样,值得我们深思。
✓ 这一衰退路径背后,是一个被广泛低估的认知规律——人对高频低风险决策的耐受度,
   远低于我们以为的。前额叶的审慎判断,会在 2-4 周内被压缩为基底神经节的反射。
```

**贡献给泥巴猪的镜像收束:**

结尾不喊口号、不强升华。用一句让人愣一下的话收束。

```
× 让我们一起拥抱 AI 时代,共同迎接未来的挑战!
✓ 我有时候会想,流水线的复杂度其实是一个组织记忆的形状。它记得每一次疼。
   但它不知道哪些疼已经不会再来了。
```

**贡献给泥巴猪的寓言化转化:**

一个真实的技术事故,可以被讲得像一则关于"完美的代价"的寓言,但不丢失工程细节。这是博尔赫斯最难学的一招,需要找到"具体事件"与"普遍命题"之间那个意外的接缝。

### 4. 三家场景配比映射表

三家配比 40/30/30 不是数学问题,落到具体句子上要按"场景—配比"做映射。

| 写作场景 | 主导味 | 操作要领 |
|------|------|------|
| 立论 / 揭穿黑话 / 反讽 | 奥威尔 | 短句、主动语态、零形容词 |
| 提出意象 / 用比喻 / 用结构说话 | 卡尔维诺 | 中长句铺陈,意象贯穿 |
| 嵌套引用 / 寓言化转化 / 收束 | 博尔赫斯 | 镜像、回旋、冷静的眩晕 |
| 描述具体事件 | 奥威尔为主,卡尔维诺点缀 | 短句叙事,关键节点用一个精确意象 |
| 推演与论证 | 奥威尔为主,博尔赫斯压底 | 层层推进,最后一句留眩晕 |
| 开头 | 看题材 | 名言起手(博尔赫斯式)/ 叙事启动(奥威尔式)/ 好奇心驱动(卡尔维诺式)|
| 结尾 | 博尔赫斯优先 | 镜像 / 眩晕 / 留白 |

### 5. 按题材调整三家配比

| 题材 | 推荐配比 | 理由 |
|------|------|------|
| 现象解读型 | 奥威尔 30 / 卡尔维诺 35 / 博尔赫斯 35 | 意象与升维是这类文章的灵魂 |
| 调查实验型 | 奥威尔 50 / 卡尔维诺 30 / 博尔赫斯 20 | 过程叙事需要奥威尔的清晰节奏 |
| 工具分享型 | 奥威尔 40 / 卡尔维诺 35 / 博尔赫斯 25 | 工具效果靠精确意象表达 |
| 技术方法论型 | 奥威尔 50 / 卡尔维诺 30 / 博尔赫斯 20 | 立场清晰最重要,博尔赫斯味降低 |
| 架构原理深度型 | 奥威尔 60 / 卡尔维诺 30 / 博尔赫斯 10 | 几乎纯分析,博尔赫斯只剩开头名言和结尾一句 |

## 二、活人感七条的正反例对照

### 第 1 条:第一人称按需在场

不止于"我觉得"。需要第一人称时,要有动作动词。第一人称是证据位置,不是段落装饰。技术方法论型文章通常保留 2-4 处,集中在亲历动作、取舍、困惑和复盘节点;技术思辨型通常保留 1-2 处;发现分享型保持 0-1 处。产品体验型和人生哲学随笔型继续按各自原有的私人视角规则执行。

```
× 这套方法可以显著降低运维成本。
✓ 我用这套方法跑了半年,运维工单从一周二十多张降到三五张。
```

技术文章没有真实亲历时,不要硬塞第一人称。可以直接写具体主体、动作和证据,也不要用"我觉得"替代来源、数据或推理。

### 第 2 条:有观点,不只是报告事实

对每个核心事实,必须有自己的反应、判断或拧巴。

```
× GitHub Copilot 在 2024 年的用户满意度调查中,得分较前一年提升 12%。
✓ Copilot 在 2024 年用户满意度涨了 12%。这个数字我看了两遍——我自己用着越来越糟,
   怎么社区评分反而涨了?后来想明白,可能是我对它的期待涨得比它的能力快。
```

### 第 3 条:段内长短句交替,段间留呼吸

```
× 流水线设计中半自动化卡点是一种由系统检测异常但由人工放行的设计模式,这种模式在初期
   通常运作良好,但随着告警频次的增加和审批人对告警的熟悉,人工审批会逐步退化为机械确认。

✓ 半自动化卡点说人话,就是系统拦一下,人点一下放行。
   这种设计听起来稳健。
   但它有个问题。审批人会越审越快,前两周认真看,第三周开始秒确认,第二个月就开始机械点。
   反射不是审核,反射只是延迟。
```

### 第 4 条:承认混合情绪与不确定

```
× 这是一项令人激动的技术进展。
✓ 我对这事的态度有点拧巴——一方面觉得它解决了我用了三年的痛点,另一方面又怀疑
   我们是不是在用一个更大的复杂度换一个更小的复杂度。
```

```
× 综上所述,服务网格是中等规模团队的合理选择。
✓ 这条结论我自己也没有十成把握。它只在我观察到的几个团队里成立,样本量不够大。
   你的环境如果跟我描述的差很多,这条结论就要重新评估。
```

### 第 5 条:真实案例为支撑

案例类型不限——踩坑、优秀实践、对比观察、失败复盘都可以。但必须真实,不能编造。

**典型案例三要素:**

1. **可识别的真实情境**——具体的时间、规模、技术栈,让读者相信这是真发生的
2. **关键转折点**——什么时候、因为什么,事情走向了一个意外的方向
3. **多一层的认知**——现在回头看,比当时多了什么理解。如果"现在的理解"等于"当时的理解",这个案例不值得写

```
× 有一次我做了一条流水线,后来发现设计有问题,就改了。
✓ 三年前我做过一条流水线,镜像扫描跑完之后,如果发现高危漏洞,流水线会停下来,
   弹一个企业微信通知,让安全同学手动点确认。当时我觉得这设计挺聪明,自动检测加
   人工兜底。三个月后我去翻数据,发现安全同学一共收到过四百多次通知,后来在群里
   发了个机器人脚本,看到关键字直接自动点确认。门禁的最后一道人,自己造了一个
   机器人来代替自己。
```

**绝对禁区:** 不允许把"踩坑"写成"我从一开始就知道有问题但被迫执行"——那不是踩坑,是甩锅。

### 第 6 条:具体地描述感受

不写抽象情绪词,写体感和动作。

```
× 看到那个 diff 的时候我非常震惊。
✓ 我把 diff 拉到第三页就停了下来,合上电脑去倒了杯水。
```

```
× 这件事让我深感不安。
✓ 我那天晚上一直在想这事,凌晨两点还在群里翻三个月前的报警记录。
```

### 第 7 条:私人视角切入

开头从一个具体的、当下的、属于"我"的场景或动作进入,不从概念进入。

```
× 在 CICD 流水线的设计中,有一类常见的反模式值得讨论。
✓ 上周我帮一个团队梳理他们的发布流程。一条主干流水线,二十七个阶段,十一个并行分支,
   四个互相依赖的人工审批,中间还塞了两个只在周二跑的安全扫描。负责人是个挺好的工程师,
   带我过完整张图之后,他问我有没有什么建议。
   我说没有。
```

## 三、长短句节奏的具体操作

### 段内节奏

每段至少一次长短交替。常见操作模式:

**模式 A:长句铺陈 + 短句锤定**

```
半自动化卡点的衰退路径相当稳定。我在不同公司、不同团队的至少 6 个样本里,观察到的
时间分布几乎一致。从第 1 周到第 9 周,审批人对告警的态度会经历一条非常清晰的退化曲线。
反射不是审核,反射只是延迟。
```

**模式 B:短句立论 + 长句解释**

```
流水线越长,沟通越糟。
原因不在工程层面,而在心理层面——每多一个节点,就多一道"这是别人的事"的心理边界,
责任的颗粒度被切碎之后,任何人都不再对整条线负责。
```

**模式 C:中长句推演 + 极短句收束**

```
你以为你在做判断,其实你在做反射。反射模式下,决策速度变快,一致性也变好,
但判别能力近乎归零。
换句话说,反射不是审核,反射只是延迟。
```

### 段间节奏

中长段后跟极短段制造呼吸。

```
[长段:300 字的机制分析]

听起来,是。

[继续展开]
```

```
[长段:案例叙述]

我说没有。

他以为我在客气。
```

### 极短句独立成段的使用场景

只在以下四类节点用,全文 3-5 处为宜:

1. **关键判断的锤定**——"反射不是审核,反射只是延迟。"
2. **情绪转折的暴露**——"我应该高兴的。" / "但我没有。"
3. **预期落空的揭示**——"听起来,是。"
4. **眩晕收束**——"我猜算。但我也说不准。"

滥用极短句会让文章变成短视频文案。一篇 4000-8000 字的文章,极短句段落不超过 5 处。

### 长句的字数上限

| 段落类型 | 单句上限 |
|------|------|
| 普通叙述 | 60 字 |
| 术语密集段落(含 2 个及以上技术术语) | 35 字 |
| 推演段落(多重逻辑嵌套) | 50 字 |

超过上限就拆。拆的方式优先用句号,其次用分号,最后才用逗号。

### 段落长度上限

| 段落类型 | 句数上限 |
|------|------|
| 普通段落 | 5-6 句 |
| 机制解释段落 | 4 句 |
| 案例叙述段落 | 8 句(但要内部有节奏变化) |

超过上限就分段。

## 四、开头名言的挑选方法论

### 四原则

1. **短**——超过 30 字的名言不用。读者扫一眼记不住的引言,等于没引。
2. **冷**——避免抒情型、励志型、煽情型名言。偏好陈述型、悖论型、冷反讽型。
3. **张力**——名言的字面意思应当与正文论点形成意外的对位,而不是简单复述。
4. **匹配气质**——技术方法论文章优先引技术权威(Brooks、Dijkstra、Knuth、Vogels、Hoare 等);非技术章节优先引文学家与哲学家(奥威尔、卡尔维诺、博尔赫斯、加缪、维特根斯坦、罗素等)。但不强求,根据论点实时挑选最贴切的。

### 挑选流程

写作前的挑选动作分四步:

1. 把本文的核心论点用一句话概括下来(不超过 30 字)
2. 提取核心论点里最关键的两三个概念(比如"完美""代价""集中化")
3. 围绕这些概念去搜索符合"短/冷/张力"的名言候选
4. 从候选里挑一句**与论点构成意外对位**的——不要挑直接说出论点的那种

### 正反例

**反例:论点是"过度抽象会失去可维护性"**

```
× 引"抽象是程序设计的灵魂"——这是正向复述论点,没有张力。
× 引"程序员应当时刻保持代码的简洁"——励志型,平淡。
✓ 引博尔赫斯"在所有的迷宫里,最完美的那种是没有出口的"——形成对位:
   你以为完美的抽象是好的,但最完美的抽象可能恰好是你出不来的那种。
```

**反例:论点是"半自动化流程会衰退"**

```
× 引"工程师要善于发现和优化流程中的薄弱环节"——空洞。
✓ 引奥威尔"有些念头蠢到只有知识分子才信得下去"——形成对位:
   半自动化听起来稳健,实际上是只有理论上聪明的人才会信的设计。
```

### 不强制使用名言起手的情况

如果题材天然适合其他开头(尤其是热点破题或调查实验型的叙事启动),可以从其他方式起手。但**名言最好挪到第二段或第三段作为"过场升维"**,而不是完全省略。

## 五、其他通用写作工具

以下工具不再展开,在本 skill 中作为通用工具箱保留:

- **节奏感的扣主线句**——偏离主线的段落必须有一句话拉回来
- **论述中的克制式打破**——中途自我质疑、半句改口、承认刚才说得不够准
- **知识"随手掏"**——知识是"聊着聊着顺手掏出来"的,不是"下面我来科普一下"
- **判断力与承认被影响**——敢下判断,且承认"我被打动了"而非"我居高临下点评"
- **诚恳务实**——不装,不表演聪明,不替读者说话,不用"假装不在意"制造反差。你是跟读者一起在场的人,不是站在高处点评的旁观者
- **对立面理解与承认**——讲观点前先把对方处境讲透,再切入自己的视角
- **人物画像法**——从一个数据点出发,用 3-5 句话想象背后那个具体的人
- **文化升维**(非技术章节)——从具体事件连接到更大的文化、哲学、历史参照物
- **句式断裂**——极短句独立成段制造重量感
- **回环呼应 / 契诃夫之枪**——前面埋的钩子后面必须响
- **谦逊铺垫法**——给出观点或建议之前,用自谦的话降低读者的防御心
- **读者直呼法**(降频)——关键节点直接跟读者对话,4000 字最多 3-5 处
- **疑问句的节奏刹车**——用疑问句让读者停一秒,准备接收新信息
- **层层剥开的修辞**——"现象→表面解释→更深的追问→核心洞察"
- **反向论证**——先满足读者的期待,然后打破它
- **案例人物的公正性**——不片面截取对论点有利的片段,讲完整故事弧
- **从业者语言**——涉及技术案例时用从业者真正会用的说法("上了 K8s"而非"使用了 Kubernetes")
- **逐一展示法 + 升番逻辑**——多个产品/工具/案例对比时,逐一展示且按"由弱到强"的升番顺序排列
- **创意案例工作法**——三类锚点(热点 / 痛点 / 炫技)+ 微型故事四步(亮挑战 → 展脑洞 → 秀过程 → 引爆结果)
- **英雄之旅叙事弧**(限调查实验型和工具分享型)——遇到问题 → 一步步去做 → 踩了坑 → 秀出让人卧槽的结果

这些工具是"可选项",不是每篇都要用全。具体使用看题材和原型。
