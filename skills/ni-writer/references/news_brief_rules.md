# 发现分享型(速读精华式)专项规则

> 核心动作:**我替你刷了一波外部资料(Reddit 帖 / 视频 / 博客 / 论文 / 推文),压缩成 3-5 分钟读完的中文精华版。**

本文件是发现分享型(速读精华式)的完整操作手册。它跟 ni-writer 的其他原型几乎反向——其他原型核心是「我自己想的」「我自己玩的」「我自己感受的」,这一种核心是「**我帮你筛过的**」。

判型决策树里,Q1 就有这个分支:「替读者把外部资料压缩成精华 → 走 2」。一旦判定为速读精华型,**剩下大部分要求亲历感、文学修饰、反直觉论断的规则都失效**。

---

## 一、整体气质画像

**「我刷得快、压缩得准、转得勤。」**

这个原型不是"亲历者",也不是"发现者",是「**信息筛选员 / 翻译官**」。它的力量来自三件事:

1. **信息源筛得好**:这篇值得转、那篇不值得转
2. **压缩得快**:5000 字原文压成 800 字中文,只留干货
3. **转得勤**:产出快、更新密、维护读者"看你不会错过 AI 圈大事"的预期

它**不需要**有自己的观点、不需要文学性、不需要升维段、不需要私人在场。它需要的是**信息密度和转化效率**。

---

## 二、标题套路(数字钩子 + 名词 + 价值钩子)

速读型的标题极其套路化,几乎只用以下 5 种模板:

### 2.1 「N 个 X」模板

最常用。`N` 是具体数字,`X` 是工具/技巧/场景:

- 「10 个真正改变我工作方式的 Claude Skills」
- 「12 个经过真实验证的 OpenClaw 使用场景」
- 「17 个让 Claude Cowork 效能倍增的最佳实践」
- 「18 条 Claude Code 高度实战化技巧」
- 「6 个分类 36 个 OpenClaw 真实场景和解决方案」

### 2.2 「N 分钟掌握」模板

- 「30 分钟掌握 Codex 95% 的能力?!不相信?一起学习:七大核心能力 + 一个彩蛋功能!」
- 「3 分钟看懂 X」

### 2.3 「X 来了」/「X 官宣」模板

强调时效:

- 「420 页 AI Agents 宝藏书籍 PDF 来了」
- 「Anthropic 发布 skill_creator 重磅优化」
- 「ChatGPT Images 2.0 官宣,实在太夸张了」

### 2.4 「反直觉对比」模板

- 「AGENTS.md 为何在 Agent 评估中碾压 Skills」
- 「X 为何在 Y 中击败 Z」

### 2.5 「时间标志/年度宣言」模板

- 「2025:Vibe 之年?Agent 之年?巨变之年!」
- 「2026 企业级 AI 编程实践手册」

### 标题写作的硬要求

1. **必须带具体数字**(10、30 分钟、420 页、95%、N 大)——抽象数字不行
2. **必须有价值钩子**:「改变」「碾压」「掌握」「重磅」「宝藏」「实在太」级别的强词
3. **允许多个标点(!?)叠加**(违反默认禁标但本原型放开)
4. **副标题 / 长题**允许:用冒号或破折号承接(违反默认禁冒号但本原型放开)
5. **标题字数 12-40**——太短没钩子,太长读者抓不住

## 三、开头公式(一句话点信息源)

速读型的开头**只有一种**:**一句话直接交代信息从哪来 + 这篇要讲什么**。

### 标准模板

```
{信息源描述},{动作动词}了{对象},{聚焦于/涵盖了/揭示了}{核心内容}。
```

### 标准示例

- 「Reddit/ClaudeAI 中看到的帖子,作者总结了自己持续测试后真正觉得有价值的 10 个 Skills,聚焦于提升生产力、自动化和专业输出,涵盖开发、文档、设计、测试等场景。」
- 「Vercel 团队最新发布了一项重要研究,揭示了一个反直觉的发现:在向 AI 编程 Agent 传递框架知识时,简单的被动方案 (AGENTS.md) 全面优于复杂的主动检索方案 (Agent Skills)。」
- 「知名开发者 Armin Ronacher 通过他从 Sentry 辞职创业的个人转折,深刻揭示了软件工程正在经历的五大巨变。」
- 「一位知名 AI 开发者、VibeCode.dev 联合创始人 Riley Brown 最新发布的 Youtube 视频 Learn 95% of Codex in 30 minutes,他表示……」

### 信息源类型常用表达

- **Reddit/帖子类**:「Reddit/ClaudeAI 中看到的帖子」「X subreddit 热帖」「HackerNews 讨论」
- **官方博客**:「{公司} 团队最新发布了一项研究」「{公司} 官方博客文章」
- **视频**:「{作者} 最新发布的 YouTube 视频」「Bilibili up 主 X 的视频」
- **论文/书籍**:「{作者} 的最新论文」「{机构}发布的 N 页报告」
- **推文/对话**:「{人物}最近发推说」「{人物}在 X 大会上提到」

### 开头硬要求

1. **必须点明信息源**——没有就别写,本原型禁止"凭空分享"
2. **必须一句话讲完**——不要铺垫"今天我要给大家介绍"
3. **可以用钩子词**:「揭示了反直觉发现」「重磅」「最新」「业界领先」
4. **不允许第一人称叙事开头**(「我最近发现」「我注意到」)——这些是 1 或 5 的写法

## 四、主体结构(二选一)

### 4.1 编号清单结构(最常用)

适用题材:技巧 / 工具 / 场景 / 最佳实践 / 推荐清单。

```
01 {工具名/技巧名}
{一句话功能}。{一句话适用场景/价值}。
  
02 {工具名/技巧名}
{一句话功能}。{一句话适用场景/价值}。
  
...
```

#### 编号格式

- **首选 01/02/03** 两位数编号
- 次选 `1./2./3.` 一位数编号
- 不要用 `①②③` 圆圈数字
- 不要用 markdown `1. 2. 3.` 列表(会被微信编辑器转格式)

#### 单条字数

- **30-150 字最佳**
- 不超过 200 字——超过就说明这条要拆成两条
- 不少于 20 字——短于这个不构成可分享的"一条"

#### 单条内部结构

每条内部三段式:

1. **第一句**:工具名/技巧名作为开头标识词,加粗
2. **第二句**:功能/做什么
3. **第三句(可选)**:适用场景/为谁有用/省了什么时间

示例:

```
01 Rube MCP Connector
通过一个统一的 MCP 服务器,将 Claude 一次性连接到 500+ 应用(Slack、GitHub、Notion 等),无需为每个应用单独配置认证。适合需要大量自动化集成的用户,大幅节省时间。
```

#### 引用别人原话的姿势

允许、且鼓励大段引用原作者的金句:

```
03 维护 CLAUDE.md
每次纠正后要求 Claude 更新规则文件,形成自我学习闭环。"Claude is eerily good at writing rules for itself."
```

英文原话可以直接保留不译。这是速读型的特色之一。

### 4.2 极简小标题结构(分析类适用)

适用题材:研究解读 / 产品发布 / 现象分析。

```
{极简小标题 1}
{2-5 句话讲清楚}。

{极简小标题 2}
{2-5 句话讲清楚}。

...
```

#### 常用小标题词库

- 「问题背景」「问题陈述」「核心问题」
- 「两种方案」「N 种思路」
- 「实验结果」「核心发现」「关键数据」
- 「三个关键原因」「N 大原因」
- 「解决方案」「解决 X 的思路」
- 「实践建议」「落地建议」「推荐做法」
- 「行业含义」「工程含义」「未来展望」

#### 每段字数

- **2-5 句话**,总长 50-200 字
- 不超过 250 字——超过就拆成两段
- 段落之间不需要过渡句,直接切下一个小标题

## 五、数据/数字密度(灵魂之一)

速读型必须有具体数字。**没有数字的速读文几乎没有传播力**。

### 5.1 数字类型

- **百分比**:53%、79%、100%、80% 减少
- **绝对数**:10 个、420 页、500+ 应用、6 个月、3-5 个
- **倍数**:3 倍、10 倍
- **价格/字节**:8KB、40KB、5 美元
- **时间**:30 分钟、5 分钟产出、单日 27 PR

### 5.2 数字密度要求

- **每 200 字至少出现 1 个具体数字**
- 全文核心断言必须用数字佐证
- 凡能量化的都尽量量化("大幅提升" → "提升 80%")

### 5.3 数字使用规范

- 数字必须有出处(原资料里有,或自己验证过)
- **不编造数字**,信不过就写"约 X" "近 X" "据称 X"
- 数字两侧用空格隔开("提升 80% 通过率" 不写"提升80%通过率")

## 六、收尾公式(原文链接 + 互动问句)

速读型收尾极简,只有两件事:

### 6.1 原文链接

明示给出原始资料的链接,允许多条:

```
原文地址
https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals

资源地址:
https://github.com/anthropics/skills
https://github.com/obra/superpowers
```

或者作为脚注引用:

```
Learn 95% of Codex in 30 minutes[1]
...
[1] https://www.youtube.com/watch?v=474wZZHoWN4
```

### 6.2 互动问句(强烈推荐)

最后一句留一个开放问题给读者:

- 「你觉得 AGENTS.md 和 Agent Skills 谁更有效呢?」
- 「你都怎么用的?评论区聊聊」
- 「半个小时,真的能让我们学习到 X 95% 的能力?不信?一起看看,看完再来评论!」
- 「这套你会用吗?哪个最戳你?」

互动问句不是硬要求,但**用了能显著提升评论率**。

### 6.3 偶尔的宣言式收尾

如果信息源本身就是宣言型(年度总结、范式判断),允许一句宣言式收尾:

- 「2025 年标志着传统软件工程秩序的瓦解。这并非职业的终结,而是'自主构建者'时代的复兴!」

宣言式收尾允许使用感叹号(违反默认禁标但本原型放开)。

## 七、标点和格式的特殊放开

速读型对默认 ni-writer 的部分禁标做了放宽:

| 默认禁 | 速读型 |
|---|---|
| 禁冒号 | **允许**——标题副标题、信息源描述、清单条目都常用 |
| 禁破折号 | 仍然禁 |
| 禁双引号 | **允许**——大段引用原作者原话 |
| 禁感叹号叠用 | **允许**——标题钩子和收尾宣言都允许 |
| 禁多问号 | **允许**——「30 分钟掌握 X 95% 的能力?!」式钩子 |

### 仍然严禁的标点

- 颜文字
- 句号叠用「。。」(应为「……」)
- 多余的空格

## 八、禁区(速读型专属)

虽然规则相对宽松,但仍有几条底线不能突破。

### 8.1 编造信息源(硬禁)

**禁止**:凭空写"最近看到一个帖子说……"但实际没有这个帖子。

要么真有真转,要么就别写。这是速读型的命根子。

### 8.2 编造数据(硬禁)

数字必须有出处。**禁止**:为了让文章好看,把"提升明显"编造成"提升 80%"。

不确定的数字写"约""近""据称",或者干脆不写数字。

### 8.3 文学修饰(硬禁)

速读型不要任何:

- 名言起手
- 「这是一个最好的时代」式文学开头
- 抒情段落
- 升维段(可以有一句宣言式收尾,但不能展开成段)
- 比喻、隐喻、象征

### 8.4 第一人称叙事段(硬禁)

允许一句"对很多人包括我自己,是 X 的一年"作为开头点缀。

**禁止**:展开任何"我做了什么 / 我看见什么 / 我突然想到"式的叙事段。那是 1 或 5 的写法。

### 8.5 反直觉论断/概念辨析(硬禁)

那是 4 技术思辨型的写法。速读型只压缩别人的论断,不自己造论断。

如果原资料本身有反直觉论断,允许转述但不允许自己再展开论证。

### 8.6 长段落(硬禁)

**单段不超过 250 字**,清单条目不超过 200 字。

任何超过这个字数的段都该拆成两段或两条。速读文的灵魂是"扫读不费力"。

### 8.7 没有清单结构的连续散文(硬禁)

如果你写完全是散文段,**不是速读型**。速读型必须有清晰的"01/02/03"或"问题背景/实验结果"式的结构骨架。

### 8.8 没有信息源开头(硬禁)

没有「Reddit 帖子说」「Vercel 团队发布」「某大佬视频」这类信息源开头,**这篇就不该走速读型**。

## 九、保留的 ni-writer 底线

虽然大部分豁免,但仍然保留以下底线规则:

### 9.1 AI 高频词全表禁用

仍然禁:赋能、生态、范式(标题除外)、抓手、闭环、链路、纵深、底座、底层逻辑、心智、复盘、对齐、拉通、颗粒度、护城河、增长飞轮。

### 9.2 套话与学究腔仍禁

禁:综上所述、值得注意的是、不难发现、本质上、归根结底、说白了、意味着什么。

### 9.3 空泛工具名禁令

不说"AI 工具""某个模型",要说具体名字。

### 9.4 促销腔仍禁

禁:蓬勃发展、欣欣向荣、熠熠生辉。

### 9.5 表演性废话仍禁

禁:"我本来没打算认真看""坦白说我是被逼的"。

## 十一、写完前的最后一遍自检(速读型专属)

通读全文,逐项打勾:

- [ ] 标题是否符合「数字钩子 + 名词 + 价值钩子」模板?
- [ ] 标题是否带具体数字?
- [ ] 开头是否一句话点明信息源?
- [ ] 主体是否走清单(01/02/03)或极简小标题结构?
- [ ] 单条/单段是否在 30-200 字?
- [ ] 全文是否散布了具体数字数据?(每 200 字至少 1 个)
- [ ] 是否给出原文链接(明示或脚注)?
- [ ] 是否有互动问句收尾?(强烈推荐,可选)
- [ ] 字数是否在 500-1500?(超过 2000 立即砍或转走其他原型)
- [ ] 第一人称是否 0-1 处?
- [ ] 是否完全没有文学修饰、抒情段、升维段、反直觉论断?
- [ ] 数据是否都有出处,不存在编造?
- [ ] 信息源是否真实存在?
- [ ] 是否清干净了 AI 高频词、套话学究腔、空泛工具名?
- [ ] 通读 3 分钟内能不能读完?(超过就说明你不是在做速读)

**最后一条是核心体感判断:3 分钟内读完且能拿走 80% 信息,才是合格的速读文。**

## 十二、和其他 4 种原型的边界(防混淆)

### 12.1 速读型 vs 1 产品体验和评价型

- **速读型**:压缩别人的资料,我没亲自玩
- **产品体验型**:我亲自下场玩了

判别:**我有没有亲自上手?有 → 1;只是看别人帖子/视频/论文 → 2**

如果素材里有"我看了 X 视频之后自己也试了一下",这就是 1 + 2 混合,**默认走 1**(亲历优先),把速读资料作为论据嵌入。

### 12.2 速读型 vs 3 技术方法论型

- **速读型**:短文(500-1500 字),清单/极简小标题为主
- **方法论型**:长文(4500-6000 字),自己输出框架 + 落地清单

如果你想写的是"自己沉淀的方法论",字数会自然超过 2000,走 3。

### 12.3 速读型 vs 4 技术思辨型

- **速读型**:压缩别人的论断
- **思辨型**:自己造反直觉论断

如果你压缩的是别人的论断,只转述不再展开,走 2。

如果你看完别人的资料后,自己再造一个反直觉论断"我看完这些 X 的研究,觉得他们其实都漏掉了 Y",那是 4。

### 12.4 速读型 vs 5 人生哲学随笔型

完全反向。速读型零文学、信息密度极高;随笔型全文学、思绪流。一般不会混。
