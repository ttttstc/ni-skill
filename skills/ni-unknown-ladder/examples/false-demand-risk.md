# 示例：伪需求风险

## 用户输入

```text
我想做一个 AI 周报生成工具，但不确定这是不是个真需求。
```

## ni-unknown-ladder 输出

```markdown
## Unknown 诊断

- 阶段：1 伪需求风险
- 置信度：高
- 判断理由：你已经提出了 feature request，但没有说明真实 pain。周报生成可能只是症状，真正问题可能是项目事实不透明、过程数据分散、风险没有及时暴露。

## 推荐下一模式

- AI 角色：产品访谈官 + 需求反方 + Framing Challenger
- 最适合的能力：office-hours / framing challenge
- 是否建议现在实现：否

## 下一阶段提示词

```text
你现在扮演「产品访谈官 + 需求反方 + Framing Challenger」。

我的 feature request 是：
我想做一个 AI 周报生成工具。

你的任务不是接受这个需求，而是判断它是不是伪需求、症状、过早解法，或者对真实问题的错误 framing。

请遵守以下边界：
1. 不要写代码。
2. 不要写 PRD。
3. 不要默认“周报生成”就是正确解法。
4. 不要一上来给完整产品方案。
5. 一次只问一个会改变产品 framing 的问题。

请输出：
1. 当前 framing；
2. 伪需求风险判断；
3. 可能被忽略的真实问题；
4. 第一个访谈问题，要求我回答具体场景；
5. 你的初步推荐；
6. 暂时不要做什么。

停止条件：明确真实 pain、目标用户、具体使用场景、现有替代方案为什么不够好，以及最小切口。
```

当前最痛的是“写周报耗时间”，还是“项目事实在写周报前就已经丢失或失真”？
