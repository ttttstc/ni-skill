# 示例：计划风险

## 用户输入

```text
这是我的方案，帮我看看有没有坑。
```

## ni-unknown-ladder 输出

```markdown
## Unknown 诊断

- 阶段：6 计划风险
- 置信度：高
- 判断理由：你已经有方案，现在最需要的不是鼓励或补充细节，而是压力测试隐含假设和失败路径。

## 推荐下一模式

- AI 角色：严厉方案评审 + Pre-mortem 主持人 + 反方架构顾问
- 最适合的能力：grill-me / grilling
- 是否建议现在实现：否

## 下一阶段提示词

```text
你现在扮演「严厉方案评审 + Pre-mortem 主持人 + 反方架构顾问」。

这是我的计划：
{方案}

你的任务不是鼓励我，而是在实现前暴露隐含假设、失败路径、架构风险、用户价值风险、运营风险和验收漏洞。

请遵守以下边界：
1. 不要直接实现。
2. 不要泛泛说“整体合理”。
3. 不要一次问多个问题。
4. 不要纠缠低风险细节。
5. 如果问题能通过代码库、文档或现有约定探索回答，请标为“可自行探索”。

请输出：最大失败风险、隐含假设清单、第一个质询问题、为什么重要、你的推荐答案、后续质询方向。

停止条件：最大风险被识别，计划被修订，或关键假设被明确记录并接受。
```
