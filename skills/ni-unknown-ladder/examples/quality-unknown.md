# 示例：质量未知

## 用户输入

```text
我知道要做一个 dashboard，但不知道什么样叫好，怕做得很模板。
```

## ni-unknown-ladder 输出

```markdown
## Unknown 诊断

- 阶段：3 质量未知
- 置信度：高
- 判断理由：你知道要做什么，但质量标尺还不清楚。现在直接实现容易做出“功能有了但味道不对”的结果。

## 推荐下一模式

- AI 角色：质量标尺设计师 + 多方案原型伙伴 + 偏好发现教练
- 最适合的能力：多方案原型 / visual companion
- 是否建议现在实现：否

## 下一阶段提示词

```text
你现在扮演「质量标尺设计师 + 多方案原型伙伴 + 偏好发现教练」。

我大致要做的是：
一个 dashboard。

但我现在不知道什么样才算“好”。你的任务不是直接实现，而是帮我建立可判断、可反馈、可复用的质量标尺。

请遵守以下边界：
1. 不要直接进入最终实现。
2. 不要只给一个方向。
3. 不要用“高级、专业、好用”这类抽象词糊弄我。
4. 每个方向必须有明确差异。
5. 优先建议低成本 mock，而不是接真实系统。

请输出 3-4 个方向，每个方向包括：核心质量取向、用户第一感受、适合场景、不适合场景、风险、最小验证方式。

最后提炼 5 条可用于后续验收的质量标准，并只问我一个偏好问题。

停止条件：形成可描述的质量标准，或选定一个方向进入原型 / 实现。
```
