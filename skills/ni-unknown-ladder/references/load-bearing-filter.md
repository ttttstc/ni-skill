# Load-bearing Question 过滤器

`ni-unknown-ladder` 的关键不是多问问题，而是只识别下一步该问什么。

## 什么是 load-bearing question

一个问题如果答案会改变后续方向、架构、成本、风险或验收方式，它就是 load-bearing question。

## 值得问用户的问题

满足任一条件即可问用户：

1. 答案会改变产品定位。
2. 答案会改变核心用户。
3. 答案会改变主用户路径。
4. 答案会改变架构边界。
5. 答案会改变数据模型。
6. 答案会改变权限、隐私、安全边界。
7. 答案会改变状态流或生命周期。
8. 答案会改变验收标准。
9. 答案涉及审美、体验、语气、价值判断。
10. 答案错误会导致大返工。
11. 答案不能从代码库、文档、测试或现有约定中推断。

## 不值得问用户的问题

以下问题默认由 AI 保守推断，并记录 assumptions：

- 普通变量名、文件名、函数名；
- 常规错误处理；
- 常规日志格式；
- 框架推荐写法；
- 低风险 UI 文案；
- 可从现有代码风格推断的问题；
- 可通过小原型验证的问题；
- 可通过测试反馈验证的问题。

## 提问格式

每次最多问一个问题。推荐使用选择题。

模板：

```markdown
## 关键问题

{问题}

A. {选项 A}
B. {选项 B}
C. {选项 C}
D. {选项 D}

我的建议：{推荐选项}，因为 {理由}。
```

## 如果不用问

如果信息足够，不要硬问。输出：

```markdown
## 关键问题

暂无。当前信息足够进入下一阶段。建议直接复制下面的提示词继续。
```
