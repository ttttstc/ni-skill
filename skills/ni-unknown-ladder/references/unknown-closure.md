# Unknown 关闭条件

`ni-unknown-ladder` 每次重新诊断时，必须判断上一个主 unknown 是否真正关闭。不要因为用户说“继续”就默认关闭。

## 关闭条件总表

| Unknown 阶段 | 关闭条件 |
|---|---|
| 0 想法空白 | 已明确它更接近工具 / 助手 / 工作流 / 产品中的哪一种；已知道第一版最应该验证什么；已明确至少一项“不做什么”。 |
| 1 伪需求风险 | 已明确真实 pain、具体用户 / 使用者、具体场景、现有替代方案为什么不够；feature request 不再只是表层功能。 |
| 2 行动未知 | 已选择第一阶段 MVP / 切口；已明确做什么、不做什么、验证什么假设。 |
| 3 质量未知 | 已形成质量标尺；至少有正例 / 反例 / 判断标准；知道什么样叫“好”。 |
| 4 表达未知 | 已沉淀 preference profile；抽象反馈被转成可执行约束。 |
| 5 决策未知 | 关键架构、数据模型、状态流、权限 / 安全边界、验收口径等 load-bearing decisions 已记录。 |
| 6 计划风险 | 主要隐含假设、失败路径、反方质询点已暴露；用户确认接受或调整方案。 |
| 7 代码库未知 | 已得到系统地图、关键模块、修改边界、风险点和最小安全修改路径。 |
| 8 实现偏移 | 偏差原因、保守处理、影响范围、是否需要用户确认已记录；重大偏差已有结论。 |
| 9 验收未知 | 已有验收用例、残余风险、手工验证步骤；用户理解关键变更或完成 quiz。 |

## 未关闭时如何处理

如果上一个主 unknown 尚未关闭：

1. 不要推进到下一阶段。
2. 明确指出缺少哪些关闭条件。
3. 继续生成面向当前 unknown 的下一阶段提示词。
4. 最多问一个 load-bearing question。

## 已关闭时如何处理

如果上一个主 unknown 已关闭：

1. 将其移入“已解决 Unknown”。
2. 从后续队列中选择下一个最阻塞 unknown。
3. 如有新信息改变优先级，重新排序队列。
4. 生成面向新主 unknown 的下一阶段提示词。
