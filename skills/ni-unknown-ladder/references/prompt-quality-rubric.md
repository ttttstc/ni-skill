# 下一阶段提示词质量评分表

`ni-unknown-ladder` 生成的提示词必须达到“可直接复制给下一轮 AI 使用”的标准。不要输出只有方向、没有执行约束的泛泛提示。

## 评分维度

| 维度 | 达标标准 | 常见问题 |
|---|---|---|
| 角色定位 | 明确 AI 扮演的专业角色，如产品访谈官、架构访谈官、严厉评审 | 只写“请帮我分析” |
| 阶段目标 | 明确本轮解决哪类 unknown | 同时要求访谈、方案、实现、验收 |
| 任务边界 | 明确不要做什么 | 没有限制，导致 AI 直接实现 |
| 提问策略 | 一次只问一个 load-bearing question | 一次列出 10 个问题让用户疲劳 |
| 输出结构 | 规定清晰的章节和字段 | 只要求“给点建议” |
| 停止条件 | 明确什么时候结束本阶段 | 对话无限延长 |
| 可复制性 | 用户复制后无需再改大量内容 | 需要用户自行补充角色、格式和边界 |

## 必须包含的 7 个组件

1. 你现在扮演「{角色}」。
2. 我的上下文是：{用户输入}。
3. 你的任务不是 {禁止事项}，而是 {阶段目标}。
4. 请遵守以下边界：{3-6 条边界}。
5. 请按以下格式输出：{结构化格式}。
6. 只问一个关键问题；如果无需提问，说明为什么。
7. 停止条件：{进入下一阶段的条件}。

## 反例

```text
帮我看看这个想法有什么问题，然后给几个建议。
```

问题：没有角色、没有边界、没有输出格式、没有停止条件。

## 正例

```text
你现在扮演「产品访谈官 + 需求反方」。

我的 feature request 是：{功能想法}

你的任务不是接受这个需求，而是判断它是不是伪需求、症状或过早解法。

请不要写代码，不要写 PRD，不要默认我的功能是正确解法。一次只问一个能改变产品 framing 的问题。

请输出：当前 framing、伪需求风险判断、可能被忽略的真实问题、第一个访谈问题、你的初步推荐、暂时不要做什么。

停止条件：明确真实 pain、目标用户、具体使用场景和最小切口。
```
