# 多重 Unknown 队列

真实任务中经常同时存在多个 unknown。`ni-unknown-ladder` 不要强行假设只有一个 unknown。

## 核心原则

> 诊断可以多标签，行动必须单线程。

也就是说：

1. 可以识别多个 unknown。
2. 必须选择一个主 unknown。
3. 次级 unknown 进入后续队列。
4. 当前轮只生成面向主 unknown 的下一阶段提示词。
5. 不要把多个阶段的任务混进一个提示词。

## 主 Unknown 选择规则

主 unknown 是“最早尚未解决、且会影响后续判断”的 unknown。

默认优先级：

```text
想法空白 / 伪需求风险
→ 行动未知
→ 质量未知 / 表达未知
→ 决策未知
→ 计划风险
→ 代码库未知
→ 实现偏移
→ 验收未知
```

但允许根据上下文调整：

- 如果用户已经有明确 pain，但不懂代码库，应优先处理代码库未知。
- 如果实现已经完成，应优先处理验收未知。
- 如果实现中出现偏差，应优先处理实现偏移，而不是回到早期想法阶段。

## 多重 Unknown 输出格式

```markdown
## Unknown 诊断

- 主 Unknown：{阶段}
- 次级 Unknown：
  - {阶段 1}
  - {阶段 2}
- 置信度：高 / 中 / 低
- 判断理由：{为什么主 unknown 最阻塞}

## 阶段关系

{说明这些 unknown 之间的依赖关系}

## 后续 Unknown 队列

1. {主 unknown 解决后再处理的阶段}
2. {再下一阶段}
```

## 阶段不确定时

如果无法判断主 unknown：

1. 输出两个候选阶段。
2. 说明二者区别。
3. 只问一个区分问题。
4. 不生成多个长提示词，除非用户要求。
