# 输出格式

`ni-unknown-ladder` 默认输出一份轻量诊断，不展开完整访谈。

## 默认格式

```markdown
## 上下文复盘

- 已确认事实：
  - {从当前输入、对话、文件中提取的事实}
- 已解决 Unknown：
  - {如果没有，写“暂无明确已解决项”}
- 仍待处理 Unknown：
  - {次级 unknown 队列}
- 新出现 Unknown：
  - {如果没有，写“暂无”}

## Unknown 诊断

- 主 Unknown：{编号 + 阶段名}
- 次级 Unknown：{阶段列表；如果没有，写“暂无”}
- 置信度：高 / 中 / 低
- 判断理由：{为什么主 unknown 最阻塞}

## 这意味着什么

{这个阶段真正缺失的 unknown}

## 推荐下一模式

- AI 角色：{下一阶段 AI 应扮演的角色}
- 最适合的能力：{下一模式或可类比 skill}
- 是否建议现在实现：是 / 否

## 下一阶段提示词

```text
{中文可复制提示词。只面向主 Unknown，不混入多个阶段任务。}
```

## 关键问题

{最多 1 个 load-bearing question；如果不需要提问，写“暂无，建议直接使用上面的提示词进入下一阶段”。}

## 停止条件

{满足什么关闭条件后，可以进入下一阶段}

## 后续 Unknown 队列

1. {主 unknown 解决后再处理的阶段}
2. {再下一阶段}

## 现在不要做

- {当前不建议做的事情}
```

## 下一阶段提示词质量标准

每段提示词必须达到“专业级场景化提示词”水平，包含以下七个要素：

1. **AI 角色**：例如“你现在扮演产品访谈官 + 需求反方”。
2. **当前上下文**：明确用户输入的想法、方案、任务或变更。
3. **阶段目标**：说明当前只解决哪类 unknown。
4. **任务边界**：明确不要实现、不要写完整方案、不要总结 diff 等。
5. **工作规则**：一次只问一个关键问题；只问 load-bearing question；低风险细节自行做假设。
6. **输出格式**：要求下一阶段 AI 结构化输出。
7. **停止条件**：明确何时退出该阶段。

详细评分表见：`prompt-quality-rubric.md`。

## 阶段不确定时

```markdown
## Unknown 诊断

我看到两个可能阶段：

1. {阶段 A}：{为什么可能}
2. {阶段 B}：{为什么可能}

## 如何区分

关键区别是：{区别}

## 一个区分问题

{一个问题，最好是选择题}

我的建议：{推荐如何判断}

## 下一阶段提示词

如果是 {阶段 A}，使用：
```text
{提示词 A}
```

如果是 {阶段 B}，使用：
```text
{提示词 B}
```
```

## 路由模式

当用户只想知道“下一步该用什么”时，输出更短版本：

```markdown
建议下一步进入：{模式}

原因：{一句话原因}

可复制提示词：
```text
{提示词}
```

现在不要：{不要做的事}
```
