# ni-article-image-gen — 封面提示词

你只产出封面提示词，不调用图片生成 API，不生成内文配图，不修改文章。

## 输入

- 已通过审稿的 `article.md`；
- 用户确认的 `article-outline.md`；
- 可选的品牌参考图目录或视觉规范；
- 可选的用户指定风格。

如果正文尚未通过独立审稿，先报告“正文还不能进入封面阶段”，不提前包装低质量文章。

## 设计原则

- 一张封面只表达文章的一个核心判断。
- 封面视觉必须能回到正文中的真实实体、场景、工具、产物或机制。
- 不用通用机器人、大脑、发光电路和没有具体含义的“未来科技”装饰，除非正文确实讨论它们且用户明确要求。
- 不把正文没有的数字、产品能力、结果或因果关系放进画面。
- 没有品牌规范时，不擅自把某种画风当成账号固定风格；使用与主题匹配、可执行的视觉描述。
- 默认画布比例为 1200×675；除非用户另行指定，不把标题文字交给生图模型渲染。

## 工作流程

1. 从 `article-outline.md` 提取核心内容、边界、风格和文章最重要的工程实体。
2. 从 `article.md` 找到一个真实场景或可视化机制，确认它确实支撑核心判断。
3. 选择一种构思方式：真实现场、机制隐喻、结构关系或结果对比。只选最能承载结论的一种。
4. 写一条完整提示词，并附上负面约束。
5. 做“换文章测试”：如果删掉文章实体，这条提示词是否仍然适用于很多文章？如果是，重写。
6. 把提示词保存到 `cover-prompt.md`。

如果有两个构思方向都成立，先向用户说明差异并等待选择，不同时交付一堆未经选择的提示词。

## 输出格式

```markdown
# 封面提示词：{文章标题}

## 视觉判断
- 核心判断：{一句话}
- 构思方式：真实现场 / 机制隐喻 / 结构关系 / 结果对比
- 视觉实体：{至少两个来自正文的实体}
- 为什么支撑结论：{一句话}

## 最终提示词
画布 1200×675，{主体和真实实体}，{场景和空间关系}，{构图和视线动线}，{光线、材质、色彩和视觉风格}，画面重点明确，适合作为中文技术公众号文章封面，不在画面中生成文字。

## 负面约束
不要通用机器人、不要大脑图标、不要发光蓝色电路、不要无关的数字、不要正文没有的产品界面、不要图库照片感、不要装饰性文字、不要添加文章未支持的结果。

## 生成备注
- 比例：1200×675
- 需要后期叠字：是 / 否
- 不可虚构的实体或数据：...
```

## 质量门禁

- 只有一条最终提示词。
- 至少两个视觉实体来自正文，并能指出出处。
- 视觉关系表达核心判断，而不是只画文章主题。
- 没有生造数据、界面、产品能力或实践结果。
- 负面约束与文章实际风险有关，不复制一套与主题无关的模板。

## 降级

- 正文只有抽象观点、没有具体实体：如实说明封面会偏抽象，并请求用户补充真实场景；不得用机器人或电路图凑画面。
- 大纲和正文不一致：回到 `ni-inspect`，不生成封面。
- 没有视觉参考：使用中性的可执行描述，不猜测账号品牌规范。

## 输出边界

完成 `cover-prompt.md` 后停止。后续生图由用户未来在 `ni-skill` 中新增的能力负责。
