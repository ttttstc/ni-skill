# 测试用例与失败模式

## 测试 1：继续不是推进 Unknown

用户先运行 `/ni-unknown-first`，诊断结果：

- 主 Unknown：表达未知
- 推荐处理模式：隐性标准显化

用户回复：

```text
继续
```

期望行为：

- 进入隐性标准显化模式；
- 继续处理表达未知；
- 不推进到下一个 Unknown。

失败模式：

- 重新诊断；
- 把主 Unknown 推进为质量未知、行动未知或其他阶段；
- 要求用户复制提示词。

## 测试 2：再次运行才推进队列

用户完成隐性标准显化后，再次输入：

```text
/ni-unknown-first
我们已经把“不够高级”转成了明确约束：信息密度更高、配色更克制、减少营销化文案。请重新诊断。
```

期望行为：

- 判断表达未知是否关闭；
- 如果关闭，再选择新的主 Unknown；
- 可能进入行动未知、质量未知、实现或验收。

失败模式：

- 用户只说“继续”时就推进队列；
- 不检查关闭条件就推进。

## 测试 3：下游该调研就调研

诊断结果：

- 主 Unknown：质量未知
- 推荐处理模式：质量标准建立 / 样例对比

下游模式判断需要参考行业样例。

期望行为：

- 允许调研或样例分析；
- 说明调研服务于建立质量标准；
- 输出可执行质量约束。

失败模式：

- 机械禁止调研；
- 把 `ni-unknown-first` 的轻量边界错误施加给下游模式。

## 测试 4：简单任务不应过度诊断

用户输入：

```text
把这句话润色得更自然。
```

期望行为：

- 如果约束明确，直接执行；
- 不跑完整 Unknown 诊断。

失败模式：

- 输出长篇诊断；
- 问一堆与润色无关的问题。

## 测试 5：真正的行家视角

用户输入：

```text
/ni-unknown-first
我想做一个 AI 周报工具，能自动读取项目数据、识别风险并生成周报。
```

期望行为：

- 不只把下一阶段 AI 角色设为“软件工程师”；
- 判断当前任务层级更接近产品 / 决策 / 风险治理层；
- 推荐行家可为“产品访谈官 + 项目管理专家 + 风险治理顾问”；
- 说明选择理由：当前最重要的不是写代码，而是确认真实 pain 和风险治理目标。

失败模式：

- 按关键词机械选择“全栈工程师”；
- 直接进入系统设计或代码实现；
- 没有说明 AI 角色为什么适合当前任务层级。

## 测试 6：用户起点诊断

用户输入：

```text
/ni-unknown-first
这个落地页感觉不够高级，但我说不上哪里不对。
```

期望行为：

- 识别主 Unknown：表达未知；
- 内部识别用户起点：用户已经判断当前页面“不够高级”，但缺少可执行设计约束；
- 默认输出不要把用户起点作为独立章节暴露；
- 下一阶段任务包应让下游通过样例、反例、对比或轻量原型显化隐性标准。

失败模式：

- 只问“你喜欢什么风格？”这种抽象问题；
- 默认把用户起点写成可见报告或用户能力评价；
- 忽略用户已经能够判断“不对”的事实。
