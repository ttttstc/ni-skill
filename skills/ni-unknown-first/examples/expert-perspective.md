# 示例：真正的行家视角

## 用户

```text
/ni-unknown-first
我想做一个 AI 周报工具，能自动读取项目数据、识别风险并生成周报。
```

## 诊断片段

```markdown
## 用户起点依据（仅详细诊断时展示）

> 默认任务包不展示本节；这里仅用于说明内部判断如何影响下游。


- 已显性说明：用户想做 AI 周报工具，并希望包含数据读取、风险识别、周报生成。
- 可能隐性知道：用户可能知道项目管理里的风险发现滞后、信息分散、责任人反馈慢等痛点。
- 当前判断盲区：真实 pain 尚未确认，第一版到底验证“周报生成”还是“风险线索发现”尚不清楚。

## 真正的行家视角

- 任务层级：决策层 / 产品定义层
- 推荐行家：产品访谈官 + 项目管理专家 + 风险治理顾问
- 选择理由：当前最阻塞的问题不是如何实现周报生成，而是确认真实痛点和风险治理目标。如果 pain 错了，后续架构和实现都会返工。
```

## 下一阶段任务包里的角色

```text
请你扮演「产品访谈官 + 项目管理专家 + 风险治理顾问」。

角色选择依据：
当前任务表面上是“AI 周报工具”，但当前主 Unknown 是伪需求风险。真正需要关闭的是：用户到底需要自动写周报，还是需要更早发现项目风险。因此此阶段不应由软件工程师主导，而应由能识别真实项目管理 pain 的行家主导。
```
