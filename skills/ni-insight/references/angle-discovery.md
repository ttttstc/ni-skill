# 角度发现：5 种角度类型

> 本文是 ni-insight 第一轮「角度发现」的参考库。一个选题能不能写得不一样，往往不是因为素材更多，而是因为切入的角度换了一个。下面 5 种是泥巴猪文章里反复出现的角度类型。

每种角度给：**它是什么 / 什么时候用 / 怎么识别它在素材里 / 真实案例 / 句式模板 / 常见陷阱**。

角度类型不是用来贴标签的，是用来逼问的。挖角度时，对着素材把 5 种都过一遍：这个选题能不能反转？能不能升维？能不能换成读者视角……过完一轮，尖的角度自己会浮出来。

---

## 1. 反转型

**它是什么**：主流认为 X 是好的 / 对的 / 该做的，你指出在某种情况下 X 恰恰是坏的。不是抬杠，是发现了一个被忽略的成立条件。

**什么时候用**：素材里有一个「人人都觉得理所当然」的共识。共识越牢，反转的张力越大。

**怎么识别**：在素材里找「最佳实践」「业界标准」「大家都在做」这类表述。它们就是反转的靶子。

**真实案例**：
- 主流说「微服务拆得越细越解耦」→ 反转「拆到一定粒度后，跨服务调用的复杂度反噬了解耦带来的收益」。
- 主流说「AI 写代码效率高」→ 反转「AI 真正的价值不是替你写得更快，是替你不写那些本不该写的代码」。

**句式模板**：
- 「大家都说 X 好，但我发现当 {条件} 时，X 反而是个负担。」
- 「X 不是错的，是被用错了场景。」

**常见陷阱**：为了反转而反转，硬唱反调。反转必须有真实的成立条件，且这个条件在现实里常见。条件太罕见的反转，读者会觉得「抬杠」。

---

## 2. 升维型

**它是什么**：读者还在第一层讨论「怎么做」，你把问题拎到第二层「这件事的本质是什么 / 它属于一类更大的问题」。

**什么时候用**：素材里全是操作层面的讨论（怎么配、怎么选、怎么修），但没人退后一步看全局。

**怎么识别**：素材里如果全是 how，没有 why 和 what-is-this-really，升维的空间就在那。

**真实案例**：
- 大家在争「CI 流水线该用 Jenkins 还是 GitHub Actions」→ 升维「这其实不是工具选型问题，是你的团队愿意为构建可复现性付多少成本的问题」。
- 大家在讨论「怎么让 AI 少写 bug」→ 升维「这是一个信任边界问题——你在把哪一类判断外包出去」。

**句式模板**：
- 「这看起来是个 {小问题}，其实是个 {大问题} 的缩影。」
- 「我们一直在回答怎么做，但更值得问的是这件事到底属于哪一类问题。」

**常见陷阱**：升维变成空泛。升到「这是一个时代的命题」就飘了。升一层就够，升到够不着地面就失去支撑。每次升维后必须能落回素材里的具体事实。

---

## 3. 利己型

**它是什么**：把一个看起来「为了团队 / 为了行业 / 为了正确」的话题，翻译成「对你个人有什么用」。从读者的自身利益重新讲一遍。

**什么时候用**：选题本身偏宏观、偏「应该」，读者容易觉得「跟我没关系」。

**怎么识别**：素材如果通篇是组织视角、行业视角，缺一个「我这个具体的人能拿走什么」的视角，利己型就有空间。

**真实案例**：
- 选题「团队该不该推行 AGENTS.md 规范」→ 利己「先别管团队，你自己今天就建一个，下次跟 AI 协作少解释半小时」。
- 选题「DevOps 文化转型」→ 利己「转型这词太大，落到你身上就是一件事：你的下班时间能不能不被半夜的告警偷走」。

**句式模板**：
- 「别管 {宏大叙事}，对你来说，这件事就是 {一个具体的个人收益}。」
- 「这事跟行业关系不大，跟你今晚几点睡关系很大。」

**常见陷阱**：利己讲成了功利鸡汤。利己型的力量来自「精确的个人收益」，不是「升职加薪」这种空头支票。收益越具体越可信。

---

## 4. 类比型

**它是什么**：把一个陌生 / 抽象 / 难懂的事，映射到一个读者熟悉的事上。好的类比本身就是论证。

**什么时候用**：选题里有一个核心机制 / 概念，直接讲很费劲，读者容易在第一屏就走。

**怎么识别**：素材里如果有一个「需要三段话才能解释清楚」的概念，它就是类比的候选。

**真实案例**：
- 解释「技术债的利息」→ 类比「它像信用卡，本金你记得，利息你忘了，等利息滚起来才发现还不动了」。
- 解释「服务网格的 Sidecar」→ 类比「它像给每个服务配了个私人翻译，服务自己只讲母语，翻译负责对外沟通」。

**句式模板**：
- 「{陌生概念} 其实就是 {熟悉的事物}，区别只在 {一个关键差异}。」

**常见陷阱**：类比不精确。类比一旦在某个关键点上失真，整个论证就塌。用类比前先问：这个类比在哪一点会失效？把失效的边界讲清楚，类比才安全。

---

## 5. 时间型

**它是什么**：引入时间轴。同一件事，放在「三年前 / 现在 / 三年后」会得出不同结论。你指出读者正站在哪个时间点上，以及这个时间点意味着什么。

**什么时候用**：选题涉及一个正在快速变化的东西（AI 工具尤其典型），静态地讨论它会失真。

**怎么识别**：素材里如果出现「以前 X 是对的，现在不一定」「再过一年这个结论可能就变了」，时间型就有空间。

**真实案例**：
- 选题「该不该自己搭 CI」→ 时间型「三年前自己搭是基本功，现在托管方案成熟了，自己搭从能力变成了负债——除非你在那个特殊的少数场景里」。
- 选题「AI 编程工具怎么选」→ 时间型「现在选哪个不重要，重要的是别把工作流绑死在某一个上，因为这个领域半年就换一轮」。

**句式模板**：
- 「这个结论三年前成立，现在 {变化了 / 快不成立了}，因为 {变量}。」
- 「你不是在选一个工具，你是在赌一个还在变的趋势。」

**常见陷阱**：把「时间型」写成「预测未来」。重点不是猜对未来，是讲清楚「时间这个变量怎么改变了判断」。预测可以错，对时间变量的分析要站得住。

---

## 怎么用这 5 种

挖角度时按顺序做：

1. 对着素材，5 种类型每种问一遍「这个选题能不能这么切」。
2. 能切的留下，挂回素材里的具体事实——挂不上的划掉。
3. 凑够 3 个候选角度，每个标上类型，进第二轮跟用户碰撞。

注意：一个选题可能同时适合多种角度，不用纠结归类。类型是挖掘的脚手架，不是输出的标签。最终 insight.md 里给核心论点标一个最贴切的类型就够。
