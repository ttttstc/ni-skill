# ni-insight — 协作模式文章策划访谈树

## 使用原则

- 问题按依赖关系分轮，不一次发完整问卷。
- 每轮最多三个当前可回答的问题。
- 每个问题说明影响，并提供编辑建议；建议不能代替用户回答。
- Agent 自己读取文件和核对事实，不把可查问题甩给用户。
- 每轮结束后等待。用户回答会改变后续问题时，重新计算下一轮。

## 提问格式

```markdown
Q1｜{决策标题}
{问题。说明这个答案会改变文章的哪一部分。}

编辑建议：{基于本周报告和素材给出的推荐方向；明确它只是建议。}
```

## 第一轮：意图与关系

当前前提：用户已经从本周报告中选了一个主题。

可问：

- 你为什么想在本周写这个题，而不是报告里的其他候选？
- 读者读完后，最希望改变一个什么判断，或者今天能试什么？
- 你与这个题的关系是什么：亲自实践、长期观察、优秀资料整理，还是准备验证？

第一轮不问文章标题、章节数量和开头句。这些决定依赖核心内容。

## 第二轮：核心内容与边界

当前前提：文章意图和作者关系已经明确。

可问：

- 如果只保留一句话，这篇文章最重要的观点或价值是什么？
- 来源里哪些做法你认同并准备忠实总结，哪些地方需要加上你的经验、调整或质疑？
- 哪些结果你真实验证过？哪些只能写成外部来源的实践？

这一轮允许的结果包括：原创判断、优秀实践总结、来源精华、方法迁移、机制解释或体验评价。不要强迫用户制造反主流角度。

## 第三轮：文章形状与风格

当前前提：核心内容、证据来源和实践状态已经明确。

可问：

- 这篇文章更接近 `ni-writer` 的哪种原型？Agent 应根据已知事实给出推荐和理由。
- 你想让文章像一次工程复盘、方法拆解、资料精读、产品体验，还是旗帜鲜明的技术评论？
- 读者需要多少背景？希望多长、第一人称多重、技术细节多深？

不要只收集“专业、深度、有温度”一类空标签，要把回答转成可执行的写作限制。

## 第四轮：结构确认

当前前提：文章原型和风格已经确认，Agent 已生成结构草案。

可问：

- 哪一节是你最想说的，是否获得了足够篇幅和证据？
- 哪一节只是资料堆砌，可以删掉或并入其他章节？
- 开头和结尾是否符合你想呈现的作者位置？

用户确认后才能把 `outline_status` 设为 `user_confirmed`。

## 常用追问

只在前一回答暴露缺口时使用：

- 你具体做了什么？输入、动作、产物和结果分别是什么？
- 什么结果与你原来预期不同？
- 有哪些日志、截图、代码、数字或失败记录？
- 这个做法在哪些条件下不成立？
- 这篇文章必须等你验证后再写，还是可以明确写成来源总结？

用户回答“不知道”时，记录未知，提出最小核验任务，不继续追问到用户被迫编答案。
