# ni-insight — 自主观点挖掘规则

本规则只用于调用状态明确为 `mode: autonomous` 的无人值守工作流。它允许 Agent 做编辑判断，但不允许冒充用户观点或用户实践。

## 启动条件

同时满足以下条件才开始：

- 已有工作流选定的候选主题；
- 本周选题报告与关键原始素材均可在本地读取；
- 原始链接、作者、发布日期和来源等级可追溯；
- 没有会改变选题成立性的未核实中心事实。

缺一项就返回 `outline_status: blocked`。不要用模型记忆或常识填空。

## 观点候选

生成 2–4 个真正不同的候选。每个候选必须包含：

- 一句话观点；
- 它解决的读者问题；
- 支撑它的来源与证据；
- 适合的文章原型；
- 成立边界或主要反例；
- 是否依赖用户第一人称实践；
- 与近期内容重复的风险。

候选可以是优秀工程实践的总结，不要求反主流。候选之间必须改变核心判断或文章任务，不能只替换标题措辞。

## 筛选

按 1–10 分评估：

1. 证据强度：中心判断是否有 A-official 或 B-original 原始来源支撑；
2. 方法密度：能否讲清动作、机制、约束、代价和适用条件；
3. 读者价值：目标读者读完后是否能改变判断或执行具体动作；
4. 可写性：现有材料能否支撑完整文章，而不是靠空泛扩写；
5. 重复风险：是否与近期文章或其他候选表达同一核心论点。

任一候选出现以下情况时直接淘汰：

- 中心事实未核实；
- 只有产品新闻、工具清单或功能复述；
- 必须依赖用户尚未提供的实践才能成立；
- 需要虚构第一人称、情绪或结论；
- 与已发布内容高度重复。

优先选择总分最高且单项都不低于 7 分的候选。没有候选过线时阻断，不降低标准。

## 自主大纲边界

- `opinion_origin` 固定为 `agent_synthesis`。
- 对来源的概括明确归因；Agent 推导出的判断明确写作综合判断。
- 不使用“我测试了”“我踩过坑”“我的项目”等未经记录支持的表达。
- 已有用户实践记录只有在来源、时间、动作、结果都可复查时才能标记 `verified`；否则使用 `source_only` 或 `not_required`。
- 如果文章主题天然要求作者实测，改选不依赖实测的观点；无法改选则阻断。

## 自检

提交前逐项检查：

- 是否确实比较了 2–4 个观点，而不是直接接受素材原论点；
- 每一节是否能映射到具体来源、证据或明确标注的 Agent 综合判断；
- 是否只有一个核心任务；
- 是否包含方法、约束、代价或反例，而非单纯摘要；
- 是否存在伪造的用户立场、第一人称或实践；
- 是否仍有会改变结论的未知项。

通过后才能写入 `outline_status: autonomous_ready`。
