# 选模块决策算法

核心原则：**够用就停，不堆。** 模块服务阅读，不负责制造文章的风格感。

## 决策算法

```text
1. 判断 ni-writer 的五种文章原型
2. 必选 verdict：来自文章核心判断；没有核心判断不输出
3. 按文章中的真实结构选择候选模块
4. 没有触发内容的候选模块直接划掉
5. 总数检查不超过 5 个
6. 输出并简短说明选择理由
```

第 4 步最重要。映射表只说明常见选择，不是模块配额。

## 文章类型映射

| 文章原型 | 必选 | 常见候选 | 说明 |
|---|---|---|---|
| 产品体验和评价型 | verdict | quote、callout | 真实判断可用 quote，注意事项或踩坑可用 callout |
| 发现分享型 | verdict | quote、callout | 原作者关键引文可用 quote，资料限制可用 callout |
| 技术方法论型（沉淀 + 深水区合并） | verdict | part、steps、callout | part 切主要论证阶段；只有真实流程才用 steps；边界和风险可用 callout |
| 技术思辨型 | verdict | part、callout | part 切主要论证阶段；反直觉判断或边界可用 callout |
| 人生哲学随笔型 | verdict | quote | 默认少加模块，避免切断思绪节奏 |

## 触发规则

- **part** 只在长章节之间需要明显视觉分隔时使用，不按 H2 数量逐个添加。
- **steps** 只包裹存在先后依赖的操作流程。原则、分类和观点清单不能伪装成步骤。
- **quote** 只包裹真实引文或文章中确实需要独立强调的核心判断，最多 2 个。
- **callout** 只包裹风险、边界、易错点或需要脱离正文提醒的内容，最多 3 个。
- **verdict** 恰好 1 个，来自正文已经完成论证的核心判断。

## 怎么判断文章类型

1. 优先读取 article.md 的 ni-writer 四层质检报告。
2. 没有报告时看主要价值：亲自体验、资料压缩、工程判断或个人思绪。
3. 工程实践、架构分析和技术方法归入“技术方法论型（沉淀 + 深水区合并）”；独立的概念辨析和技术判断归入“技术思辨型”。
4. 仍拿不准时问用户，不根据小标题数量或是否存在清单猜类型。

## 总数控制

模块总数上限 5。verdict 占 1 个名额，其余模块按文章真实需要选择。

| 模块 | 上限 |
|---|---|
| verdict | = 1 |
| part | ≤ 文章主要阶段数 |
| callout | ≤ 3 |
| quote | ≤ 2 |
| steps | ≤ 1 |

超过上限时，优先保留 verdict。其他模块按“去掉后是否损伤理解”排序，作用最小的先删。

## 典型组合

| 文章 | 类型 | 可能的组合 |
|---|---|---|
| 怎么评估 AI 编程工具 | 技术方法论型（沉淀 + 深水区合并） | verdict + part×2 + steps |
| 服务网格的代价 | 技术思辨型 | verdict + part×2 + callout |
| 一篇论文的三条发现 | 发现分享型 | verdict + quote + callout |
| 我第一次使用某个产品 | 产品体验和评价型 | verdict + quote + callout |

“可能”是关键。文章没有真实触发点时，只有 verdict 也可以。
