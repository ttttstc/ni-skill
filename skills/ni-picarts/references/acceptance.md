# 验收

## 先校准质感

同一底图、遮罩、renderer、尺寸和光源下，只换法线做 A/B 对照。诊断模式可全幅显示，正式交互须恢复擦拭。

至少看全图与脸、手、衣褶/机械关节的 100% 局部，在左、中、右光源下检查：

- 五官与手部清楚，高光不吞掉眼鼻或指节。
- 高光随曲面连续改变，衣褶边缘窄而圆，不是大块软亮带。
- 金属暗部仍能认出结构；没有紫色数据色、脏颗粒或错误凹凸。
- 轮廓、细实体、内部空气均正确；无遮挡实体外的金属光斑。

没有旧版或原站参照时使用技能随附认可样片作质感锚点，但不把不同构图的像素差当成质量分数。样片质感不达标，先定位底图、法线或遮罩；不要以资源加载、像素变化、模型成功或高分辨率替代视觉结论。

## 资产与运行

1. 底图、法线、mask、clip 同尺寸并配准；认可底图哈希不变。遮罩外法线归平，clip alpha 与 mask 一致。
2. 用本地 HTTP 打开产物，纹理、模块和云图全部加载，无控制台/资源错误。禁止只双击 `file://` 后把模块加载失败归因于素材。
3. 默认入场时间 4.7 秒，金属 0.85，消退 0.58；笔刷按当前需求或认可样片核对。
4. 桌面移动鼠标能留下擦痕；按住时不侵蚀；释放并移开后消退。触控移动显露、结束后消退；不要求手机长按等同于桌面鼠标按钮。
5. 桌面和窄屏完整显示原比例，无横向溢出、裁切和挤压。真实长竖图需另查完整页面布局。

随附 `verify_preview.mjs` 对模板执行上述运行检查并保存截图；它不为新作品的视觉质量打分。`qa` 报告中保持 `visualReview: not-assessed`，实际审视后在另一个结论中记录结果。

## 背景隔离必须量化

在当前画布分辨率下，以同尺寸缩放的 clip alpha 定义前景与背景。所有 `alpha === 0` 的背景像素都纳入检查，不能只挑四个角落。

- 擦拭前后 `backgroundMaxDelta === 0`。
- 每个背景像素与约定墙色的 RGB 最大误差为 0。
- 全幅金属显示、移动光源、按住和消退后重复检查；边缘不能出现外向光晕。

抗锯齿边缘的部分覆盖像素单独看，不放宽零覆盖区域的标准。没有背景采样或前景采样时检查失败，不能用空集合算通过。自动报告须记录采样数量。

## 可搬走的交付

HTML、JS、Three.js、云图和每张纹理都随产物保存，使用相对路径。换到独立目录、重新启动 HTTP 服务后复验，不依赖原项目目录、缓存、绝对路径或在线 CDN。压缩包另解压复验，别只看 ZIP 存在。

按实际状态报告：

| 状态 | 能证明什么 |
|---|---|
| 素材生成 | 已有文件与提示词 |
| 材质整理通过 | 尺寸、mask/clip、哈希等数据一致 |
| 运行通过 | 真浏览器中的加载、互动、消退和背景隔离 |
| 视觉通过 | 已实际检查形体、配准和多光源细节 |
| 用户认可 | 用户认可了指定版本，可依授权扩展 |

触控模拟不写成实体手机验收。原 shader 哈希一致不写成新作品逐像素复刻；二维生成法线不写成原三维几何。只做静态模式不宣称动态通过。
