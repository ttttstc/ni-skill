# ni-article-image-gen — 配图 prompt 生成

> 这是泥巴猪的公众号创作套件里的配图 skill。它只产出结构化的图像 prompt，不直接调 API 出图。

你现在的任务是给一篇文章想配图：**1 张封面 + 9 张内文配图**，每张给一条能直接拿去生图的 prompt。出不出图、用什么工具出，由用户自己定。

**风格默认黏土定格动画。** 用户没特别说，就用黏土风；用户指定了别的风格（水彩、扁平插画、像素风、胶片感……），就整套切到那个风格。无论哪种风格，**一篇文章里 10 张图必须是同一种风格**。完整的风格定义和切换规则见 `references/visual-prompts.md`。

## 这个 skill 在管线里的位置

ni-article-image-gen 是 P1 skill，不阻塞发布闭环。它读 `article.md`（+ 可选 `insight.md`），产出 `images/cover-prompts.md` 和 `images/inline-prompts.md`。用户拿 prompt 去生图，再自己上传。

## 原则

- **实体锚定**：每条 prompt ≥ 2 个文章实体。「黏土做的」「水彩画的」是风格，不顶实体。
- **风格一致**：整篇 10 张共用同一个风格块，不混风格。
- **数量固定**：1 封面 + 9 内文，不多不少。文章撑不起 9 张就显式降级。
- **不堆装饰**：找不到合适触发点的模块或位置就不放，不凑。

## 输入

**独立运行模式**：用户给 `article.md` 路径或粘贴文章；可选给 `insight.md`（核心论点帮封面定调）；可选指定风格。
**被 workflow 调度模式**：workflow 注入 `article.md` + `insight.md` 路径和 `images/` 输出目录。

## 风格：默认黏土，支持切换

**判断流程**：

1. 用户的输入里**提到了具体风格**（「我想要水彩的」「用扁平插画」「像素风」）→ 用用户指定的风格。
2. 用户**没提风格** → 默认黏土定格动画。不用专门问，直接用，并在交付时告诉用户「默认上的黏土风，想换直接说」。

**默认风格——黏土定格动画**一句话定义：所有元素都是手工黏土（橡皮泥）捏出的实体模型，放在微缩实景搭景里，用定格动画方式拍摄；表面有指纹和捏塑痕迹，柔和影棚暖光，参考 Aardman 定格动画的体积感。

**切到其他风格时**：按 `references/visual-prompts.md` 第 1 节的「风格块结构」，为用户指定的风格写一个等价的完整风格块（材质 / 场景 / 灯光 / 触感 / 参考）。结构不变，只换风格内容。

不管用哪种风格，**整篇 10 张图共用同一个风格块**，不混风格。

## 封面：1 张

封面只产 1 条 prompt。先判断这篇文章封面该走哪个**构思方向**，再用当前风格落地：

| 构思方向 | 做法 | 适合的文章 |
|---------|------|-----------|
| 直觉冲击 | 用一个场景视觉化核心观点 | 热点类、观点类 |
| 氛围渲染 | 把文章里最有画面感的真实场景表现出来 | 故事类、情绪类 |
| 结构具象 | 把文章的核心结构（几条标准、几个步骤）做成一组小物件排列 | 干货类、清单类、测评类 |

只产 1 条最终封面 prompt。拿不准走哪个方向时，可以把判断讲给用户听，让他点头再定。

## 内文配图：固定 9 张

每篇文章固定产出 9 条内文配图 prompt。9 张要**铺满全文**，不堆在一处：

- 第 1 张：开头场景 / 钩子的视觉化
- 第 2-8 张：按文章章节和核心论点分布，每个主要章节 1-2 张，每个核心判断配 1 张
- 第 9 张：结尾 / 落地路径的收束画面

每张选一个最合适的**构图类型**（构图类型与风格无关，任何风格下都适用）：

| 构图类型 | 适用内容 | 构图核心 |
|---------|---------|---------|
| infographic | 数据、统计、指标对比 | 数字牌 + 区域分块 |
| scene | 叙事场景、情绪渲染 | 主体 + 场景 + 氛围光 |
| flowchart | 流程、步骤、工作流 | 节点 + 箭头，搭成流程 |
| comparison | 两个方案 / 观点对比 | 左右分栏两组物件 |
| framework | 概念模型、架构关系 | 积木堆出层级结构 |
| timeline | 时间线、发展历程 | 里程碑沿时间轴排列 |

6 种类型的 prompt 模板见 `references/visual-prompts.md`。

## 实体锚定（真实优先的落点）

每条 prompt——封面和 9 张内文都算——**必须包含至少 2 个文章实体**。

实体指文章里真实出现的：工具名（Claude Code、Argo CD）、具体概念（上下文债、Sidecar 代理）、场景（凌晨的告警、第三次失败的流水线）、对象（一份 AGENTS.md、一条调用链）。

**自检标准**：把 prompt 给一个没读过文章的人看，他能不能猜出文章大概在讲什么？能猜出 → 锚定到位。猜不出 → 不合格，重写。

风格本身不算实体——「黏土做的」「水彩画的」是风格，不是内容。锚定要靠文章里的具体东西。

## 视觉一致性

整篇文章的 10 张图要让读者觉得出自同一套。两个一致项：

1. **风格一致**：10 张图共用同一个风格块（默认黏土，或用户指定的那一种）。
2. **色板一致**：给整篇文章定一组 2-3 色色板，写进 `cover-prompts.md` 开头，10 条 prompt 统一带这组色板。

## 输出

### images/cover-prompts.md

```markdown
# 封面 prompt：{文章标题}

## 风格与色板（全文统一）
- 风格：黏土定格动画（默认）/ {用户指定的风格}
- 主色：{色名 + hex}
- 辅色：{色名 + hex}

## 封面
- 构思方向：直觉冲击 / 氛围渲染 / 结构具象
- prompt：{完整 prompt = 风格块 + 构图描述 + ≥2 文章实体 + 色板}
- 锚定实体：{实体 1}、{实体 2}
```

### images/inline-prompts.md

```markdown
# 内文配图 prompt：{文章标题}（共 9 张，风格：{当前风格}）

## 配图 1（位置：开头）
- 构图类型：scene / infographic / flowchart / comparison / framework / timeline
- prompt：{完整 prompt = 风格块 + 构图描述 + ≥2 文章实体 + 色板}
- 锚定实体：{实体 1}、{实体 2}

## 配图 2（位置：第 X 节）
...

## 配图 9（位置：结尾）
...
```

## 硬规则

- **封面 1 张，内文 9 张，固定。** 不多不少。
- **整篇 10 张图同一种风格。** 默认黏土；用户指定别的就整套切，但不混风格。每条 prompt 都附完整风格块。
- **每条 prompt ≥ 2 个文章实体。** 锚不上就别出这条。
- **9 张内文要铺满全文**，不许挤在一两节。
- **禁止泛化词**：科技感、未来感、商务感、高级感——这些不是实体，也不是风格描述，不许用来凑。

## 验收

- **输入合法**：文章就绪；封面 1 张、内文恰好 9 张。
- **输出对齐**：cover-prompts.md / inline-prompts.md 结构完整，字段齐全，风格和色板已定。
- **实体锚定 + 风格一致**：每条 prompt 实测 ≥ 2 个文章实体、过「没读过文章能否猜出主题」测试；10 条 prompt 风格块一致、色板一致。
- **交付前自查**：通读所有 prompt，问两个问题——「换篇文章这些 prompt 还成立吗」（成立说明锚定失败）、「风格块够不够具体，能不能稳定生成目标风格、而不是泛泛的插画」（不够说明风格块要加细节）。

## 降级

| 场景 | 降级路径 |
|------|---------|
| 文章实体太少，锚不出 2 个 | 不硬编泛化 prompt。告诉用户「这篇能锚定的具体实体不够，配图会很空，要不要先在文里补点具体细节」。 |
| 用户指定了一个很模糊的风格（如「好看点的」） | 不擅自猜。问一句「你说的好看是偏哪种——黏土、水彩、扁平插画还是别的」，给几个具体选项。 |
| 没有 insight.md | 照常做，封面定调改从文章本身推断核心观点，提示用户「没拿到核心论点，封面方向我自己揣摩的，你校一下」。 |
| 文章太短，铺不下 9 张 | 显式告诉用户「这篇字数撑不起 9 张，硬塞会重复，我建议 X 张」，按实际给，不硬凑到 9。 |

降级显式标注。
