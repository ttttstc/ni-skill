# 5 个排版模块的转译规则

> 本文是 ni-formatter 的模块库。5 个模块：part / callout / quote / steps / verdict。每个给：触发判断 / 注释语法 / 约束 / 正反例。

注释只**包裹**原文，绝不改写正文。

---

## part — 章节分段

**触发**：H2 标题前。技术章节（方法论型 / 架构原理型）的每个 H2 强制加；非技术章节按需。

**语法**：在 H2 标题前单独一行写 `<!-- :::part 标题文字 -->`，原 H2 标题保留不动。

```
<!-- :::part 二、机制拆解 -->
## 二、机制拆解
```

**约束**：数量 ≤ 文章 H2 总数。不给非技术章节的口语化转场（「说到这个」）加 part。

**正例**：技术文章「一、二、三」每节前加 part，下游渲染成分隔线 + 标题强调。
**反例**：给一篇一口气顺下来的现象解读文每段都加 part，把文章切碎。

---

## callout — 提示 / 警告 / 重点

**触发**：段落里出现「注意 / 警告 / 容易踩坑 / 反直觉」这类信号。

**语法**：`<!-- :::callout 类型 -->` 段落 `<!-- ::: -->`。类型三选一：
- `warning` 技术警告（会出事的坑）
- `info` 中性提示
- `tip` 经验技巧

```
<!-- :::callout warning -->
直接在生产分支跑这个命令会清掉未提交的改动，先确认。
<!-- ::: -->
```

**约束**：≤ 3 个。同一段不重复包。

**正例**：把「这一步漏了会导致 token 泄露」包成 warning。
**反例**：把一段普通陈述包成 callout，只为了「显得有重点」。

---

## quote — 引用 / 金句

**触发**：开头的名言；文中可独立截图转发的金句。

**语法**：`<!-- :::quote -->` 内容 `<!-- ::: -->`。有出处的在内容里标出处。

```
<!-- :::quote -->
你不是在选一个工具，你是在赌一个还在变的趋势。
<!-- ::: -->
```

**约束**：≤ 2 个。金句 ≤ 30 字。名言遵循「短 / 冷 / 张力」。

**正例**：开头名言包一个，文中最尖的那句判断包一个。
**反例**：把一段三句话的说明包成 quote，金句不是越长越好。

---

## steps — 步骤流程

**触发**：出现「第一步 / 第二步」，或 ≥ 3 条的编号操作流程（落地路径常见）。

**语法**：`<!-- :::steps -->` 步骤列表 `<!-- ::: -->`。每步开头加粗。

```
<!-- :::steps -->
1. **统计服务数量**，先有个数。
2. **估算调用链深度**，找最长的那条。
3. **标出跨服务的强依赖**，这些是拆分的阻力。
<!-- ::: -->
```

**约束**：≤ 1 个。总步骤 ≤ 7。纯抒情 / 纯观点文章不放。

**正例**：技术方法论文的落地路径包成 steps。
**反例**：给现象解读文里「我先注意到 A，再想到 B」这种叙事顺序硬套 steps。

---

## verdict — 核心判断

**触发**：从核心论点（独立运行时用户给，workflow 模式从 insight.md 读）出发，在文章里找到**首次完整呈现该论点**的那一句。

**语法**：`<!-- :::verdict -->` 核心判断句 `<!-- ::: -->`。

```
<!-- :::verdict -->
AI 真正的价值不是替你写得更快，是替你不写那些本不该写的代码。
<!-- ::: -->
```

**约束**：全文恰好 1 个。位置通常在第一节末或开头铺垫之后。找不到对应句不硬挑，走 SKILL.md 的 降级。

**正例**：包住文章里那句立场最鲜明的核心论点。
**反例**：随便挑个段尾结论句当 verdict，跟真正的核心论点不是一回事。

---

## 通用红线

- 注释包裹原文，**一个字都不改**。
- 去掉所有注释后文章必须仍可读。
- 找不到合适触发点的模块——不放，别凑。
