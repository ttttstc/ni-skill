## 1. 学习任务模型

维护以下内部模型：

```yaml
learning_mission:
  topic:
  user_goal:
  target_capability:
  reader_background:
  time_budget:
  source_scope:
  output_depth:
  gate_mode: strict
```

学习任务会改变知识选择。客户会议优先关注角色、业务机制、概念区分、未知项和专家问题。方案设计优先关注对象、流程、状态、规则、边界、例外和约束。一般学习优先关注心智模型、机制、案例和迁移能力。

## 2. 资料清单

分析前，为每个资料或有意义的资料片段维护一行记录：

| 字段 | 含义 |
|---|---|
| 标识 | 例如 S1 的稳定标识 |
| 类型 | PDF、书籍、报告、网页、视频、幻灯片、图表、音频、转录或笔记 |
| 角色 | 权威参考、研究、培训、内部约定、专家意见、会议讨论、营销材料或未验证主张 |
| 可访问性 | 完整、部分可读或不可用 |
| 覆盖范围 | 实际检查过的页码、章节、时间戳、幻灯片或小节 |
| 视觉或口语上下文 | 会影响含义的视觉关系、说话者背景、指代、演示和试错过程 |
| 结论与案例 | 承重结论和承载推理的案例 |
| 问题 | 冲突、缺页、提取错误和未解决问题 |

约定范围内的资料只要仍是部分可读或不可用，就不要进入蓝图。请求能够解除阻塞的最小缺失材料。

处理长资料或多份资料时：

1. 按章节、论证、会议场次或主题等语义边界切分。
2. 完成一个单元后记录完成状态，再进入下一个单元。
3. 保留结论、概念和案例与资料标识的关联。
4. 对不同资料中的重复术语和冲突定义进行对照。
5. 最后复核资料清单，确保约定范围内没有资料从模型中消失。

## 3. 有边界的完整性

先识别全部内容，再决定展开深度。使用四类分级：

- **核心**：删去后会破坏主线理解、判断、应用或专家对话。逐项列出并完整讲解。
- **桥接**：为关闭特定认知缺口所需的前置概念或区分。只讲到解除阻塞为止。
- **外围**：资料中出现但对当前学习任务价值较低的内容。有意义时在主动舍弃项中点名，不展开。
- **范围外**：超出约定资料或学习任务的内容。当读者可能误以为已覆盖时，说明边界。

案例使用同样规则：

- 展开每个承载推理的案例。
- 只有在保留强调重点后，才能合并完全重复的案例。
- 舍弃装饰性轶事和跑题内容。
- 对不明显的舍弃，在蓝图中记录内容和理由。

这是完整性规则，不是建立百科全书的邀请。

## 4. 最小充分领域模型

建立六个相互连接的部分：

1. **根本问题**：领域为什么存在，解决什么根本问题，没有这些方法会怎样。
2. **核心对象与角色**：建立心智模型所需的人、角色、系统、对象、资源和状态。
3. **核心概念**：与学习任务相关的高影响概念，以及必要的桥接概念。
4. **机制**：一个状态为什么导致另一个状态，包括约束、激励、资源流和反馈环。
5. **判断规则与边界**：证据、识别规则、方法选择、推翻条件、例外和失败模式。
6. **案例与未知项**：代表性、对比性、失败和边缘案例，以及资料无法回答的问题。

对每个候选概念追问：

- 后续哪些推理依赖它？
- 它解释哪个机制？
- 误解它会导致哪种真实判断失败？
- 是否必须掌握它才能跟上专家对话？
- 对当前学习任务而言，它属于核心、桥接、外围还是范围外？

## 5. 关系图

显式标出关系。可用的关系类型包括前置、组成、顺序、状态转换、因果、反馈、对比、例外、约束和证据。

不要输出没有结构的概念清单。说明为什么这些分组对于当前学习任务是完整的，组内概念如何关联，以及各组如何合成一张心智模型。

## 6. 学习主线

构造最短但充分的因果路径：

```text
真实问题
直觉方案失败
缺失机制
第一个核心概念
新的限制或后果
下一个概念
判断规则
例外或边界
可执行判断
```

优先考虑认知依赖，而不是资料顺序。只有当历史或试错顺序本身解释机制时，才保留时间顺序。每一节都要自然产生下一节要回答的问题。
