# 认知缺口与证据完整性

## 目录

1. 缺口模型

3. 搭建桥梁
4. 证据状态
5. 冲突与不确定性

## 1. 缺口模型

一个认知缺口包含四个字段：

```yaml
cognitive_gap:
  blocked_understanding:
  missing_bridge:
  why_reader_would_get_stuck:
  repair_strategy:
```

有用的问题不是「这属于哪一类」，而是「什么具体缺失的连接，让读者无法从 A 走到 C」。

## 2. 检测步骤

检查每个重要的推理转折，寻找：

- **术语缺口**：继续推理前必须理解某个术语。
- **前置知识缺口**：资料假定读者已经知道更早的模型、流程或约束。
- **机制缺口**：只说 A 导致 C，没有解释中间的 B。
- **区分缺口**：相似概念被当成可以互换，但后果并不相同。
- **应用缺口**：定义给了，却没有告诉读者如何判断或操作。
- **边界缺口**：缺少失效条件，导致规则看起来像无条件成立。
- **隐藏约定**：内行依赖某种规范、默认值或角色期待，却没有说出来。
- **视觉上下文缺口**：文字依赖图表、趋势、空间关系或演示。
- **专家简写缺口**：代词、省略或压缩论证隐藏了必要内容。

同时检查四个常见跳跃：

1. A 为什么导致 B，中间的机制是什么？
2. 它和最相近的概念有什么区别？
3. 在什么条件下规则会失效？
4. 什么证据能让实践者识别并使用它？

## 3. 搭建桥梁

只修复缺失的连接：

```text
读者无法理解 X
因为缺少 Y
因此补充 Z
然后验证 Z 是否重新接上原来的推理
```

选择最小有效桥梁：白话定义、前置知识、因果链、对比、反例、具体场景、用文字还原视觉关系，或判断规则。

不要把每个术语都教成一章。如果删去某段解释后推理仍然连续，就让上下文承担理解任务。

## 4. 证据状态

内部维护以下状态，并对承重结论公开：

- `SOURCE`：由指定的原始资料明确支持。
- `INFERENCE`：通过可见推理链从原始资料推导出来。
- `EXTERNAL`：从指定外部来源补充，用于关闭关键认知缺口。
- `UNKNOWN`：当前证据不支持。
- `NEED VALIDATION`：可以讨论，但不能在实际决策中当作已确定事实。

安全推导必须同时满足：

1. 前提存在于原始资料中。
2. 推理链可以展示，且没有偷偷加入事实前提。
3. 没有资料冲突推翻结论。
4. 表述准确传达不确定程度。

任一条件不满足，就进行外部核验或保留为未知项。

## 5. 冲突与不确定性

资料不一致时：

1. 说清楚争议的具体位置。
2. 判断差异来自定义、范围、时间、激励还是证据不同。
3. 说明接受各自说法会得到什么结论。
4. 说明仍然能够得出什么结论。
5. 标出还需要验证的内容。

不要制造共识。不要为了让文档显得完整而填补空白。未知项是对话准备度的一部分，因为它告诉读者哪些地方不能装懂。
