# ni-radar — 本周选题报告契约

## 扫描范围

1. 递归读取用户指定素材库中的 `.md` 文件。
2. 排除 `选题指南/` 和用户指定的其他输出目录，防止把旧报告当成新素材。
3. 从 frontmatter 优先读取 `url` / `source`、`title`、`author`、`published` 和 `captured_at`。
4. `published` 缺失时回到直接来源核验；不能核验则淘汰。
5. 读取输出目录中的历史 `选题指南-*.md` 做论点去重；如果用户提供已发布日志，同时读取日志。

## 第一行

只能使用以下两种开场之一：

```text
本周大题：{明显压过其他候选的主题与原因}
```

```text
本周没有足够强的 5 个选题，只有 {N} 个过线。
```

没有大题且候选充足时，第一行写：

```text
本周有 {N} 个过线选题，建议优先写第 {X} 和第 {Y} 个。
```

## 报告结构

```markdown
{第一行结论}

## 调研范围
- 运行日期：YYYY-MM-DD
- 时间窗口：YYYY-MM-DD 至 YYYY-MM-DD，共 21 天
- X 主动检索窗口：YYYY-MM-DD 至 YYYY-MM-DD，共 14 天
- 本地素材库：{绝对路径}
- 扫描文件：{数量}
- 外网新增来源：{数量；X 长文数量单列}
- 系统深化：{/last30days 调用次数 / 未安装或不可用时的降级原因 / 本周无需调用}
- 历史去重：{已发布日志 / 历史选题报告 / 能力受限}
- 本周内容范围：{用户输入 + 素材实际覆盖}

- 推荐理由：{为什么现在值得写，以及用户能提供什么}
- 暂不推荐：{主要缺口}

## 候选 1：{直白标题，不炒作}
- 推荐级别：本周主推 / 备选 / 暂缓
- 内容方向：{用户指定方向或从素材归纳出的方向}
- 原始标题或核心话题：
- 参考文章锚点：{标题、作者、原始链接，以及本文实际讨论的具体方向}
- 深化主题：{紧贴参考文章的具体对象 + 工程动作或机制 + 问题、结果或边界}
- 分析方式：{/last30days / ni-radar fallback / 无需系统深化}
- 系统分析摘要：{近期讨论、实践方法、争议、反例和适用边界；未执行时写原因}
- 覆盖限制：{实际覆盖的平台和缺失项；不得把未返回写成没有讨论}
- 作者及来源：
- 原始链接：
- 发布时间：
- 热度或讨论度依据：{公开数字、评论质量或传播证据及采集时间；没有则写 unknown}
- 发生了什么：{2–3 句，只写事实}
- 来源：
  - 核心一手来源：{直接链接}
  - 补充一手来源：{没有则写无}
- 日期：{核心事件日期；辅助材料日期另注}
- 核心观点摘要：{忠实概括来源，不写成用户已确认观点}
- 为什么与受众有关：{1 句}
- 为什么值得写成公众号文章：{适合深度思考、二次研究或工程迁移的原因}
- 较少被讨论、值得与用户验证的角度：{这是候选，不是用户已确认观点}
- 建议的中文文章切入角度与标题：{候选方案，等待 ni-insight 与用户确认}
- 可进一步深挖的争议点或工程问题：
- 可用证据：{截图、基准、代码、日志、价格、版本、真实数字或 none}
- 与用户实践的连接：{已知内容；未知时写需要讨论的问题}
- 深度：ONE / TWO
  - ONE：{唯一成立的文章命题}
  - TWO-A：{仅 TWO 时填写，第一个独立命题}
  - TWO-B：{仅 TWO 时填写，第二个独立命题和独立证据}
- 风险与缺口：{事实、实践、时效或证据风险}
- 为什么占一个位置：{1 句}

## 淘汰记录
| 素材或主题 | 原因 |
|---|---|
| ... | UNVERIFIED / 超过 21 天且无本周影响 / 重复论点 / 二手来源 / 方法密度不足 |

## 需要用户决定
1. {会改变本周主推选择的问题}
2. {需要真实实践或验证的问题}
```

候选按推荐顺序排列。前五个必须全部过硬门槛；第六到第八个只有在同样过线时才加入，不能作为凑数区。

排除工具清单、产品推荐、促销、广告、软文、纯新闻搬运和缺乏实质观点的内容。候选应集中在工程实践、方法论、系统设计、Agent / Skill / Workflow、AI 辅助研发、认知框架或有事实支撑的行业判断。

生成前按原始链接、核心话题和切入角度检查历史报告。即使换了标题，只要中心论点和工程问题高度相似，也视为重复，不连续多天推荐。

## 保存与返回

- 默认文件：`D:\0-brain\raw\素材池\选题指南\选题指南-YYYY-MM-DD.md`。
- 如果同名存在，使用 `-v2`、`-v3`，不覆盖旧报告。
- 写入成功后，仍须在聊天中返回完整 Markdown。
- 写入失败时，在聊天中返回完整报告和准确错误，不把保存失败说成任务完成。
