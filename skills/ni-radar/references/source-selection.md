# ni-radar — 来源筛选规则

## 一手来源边界

| 来源 | 可以支撑 | 不能单独支撑 |
|---|---|---|
| 官方工程博客、文档、Release | 产品能力、版本、机制、价格、官方案例 | 独立用户的真实效果 |
| 原作者 X 长帖、博客、播客 | 作者自己的方法、实践、判断和结果 | 未经核验的产品通用事实 |
| GitHub Issue、Discussion、设计文档 | 可追溯问题、决策、代码和维护者说明 | 超出具体仓库的普遍规律 |
| Hacker News 原评论 | 评论者明确讲述的个人实践和争论 | 产品事实、行业共识、评论者身份未证明的结论 |
| 媒体、转载、摘要 | 发现原始来源的线索 | 入选选题的关键事实 |

找不到 `A-official` 或 `B-original` 的候选标记 `UNVERIFIED` 并淘汰。

## X 优先策略

优先搜索两类账号：

1. AI 工程领域有持续原始产出的研究者、工程师、产品负责人、创始人和团队成员；
2. 用户在调用中提供的关注博主名单或名单文件。

在第一类账号中，优先检查 Anthropic / Claude 团队成员、OpenAI、Google DeepMind、GitHub 等一线研究与工程团队及其成员的原创分享；名单不是封闭白名单，仍以内容是否来自真实实践、是否有方法密度为准。

“知名”不能只按粉丝数判断。优先依据公开身份、长期原始作品、真实项目和持续讨论质量。用户关注名单为空时，只能使用第一类公开证据，不得替用户虚构关注关系。

优先保留能够完整展开方法、决策、证据和限制的 X Article、长帖或 Thread。短推文、转帖和一句结论只能用于发现原文。

## 方法密度硬门槛

候选至少回答下列两项，其中一项必须是“做法”或“证据”：

- 解决什么具体工程问题；
- 采用了什么步骤、流程或判断框架；
- 哪个约束或决策改变了方案；
- 有什么代码、日志、截图、基准、价格或结果；
- 哪种情况下失败，代价是什么；
- 适用前提和边界是什么。

纯发布新闻、工具清单、融资消息、泛泛趋势判断和没有原始材料的二手解读不过线。

## 选题颗粒度

每个候选必须锚定至少一篇已经读完的一手参考文章，并收敛到一个具体工程问题。用于系统深化的主题应包含：

- 具体对象：工具、系统、流程、模型、团队角色或工程环境；
- 工程动作或机制：如何设计、运行、协作、测试、部署、评估或治理；
- 具体问题、结果或边界：解决什么、改变什么、何时失败、代价是什么。

主题必须紧贴参考文章实际讨论的方向。不得因为原文提到 Claude Code 的一个上下文管理方法，就扩张成“Claude Code 最佳实践”；不得因为文章讲一个 Agent Workflow，就扩张成“AI Agent 发展趋势”。

检验方法：主题中的关键名词和判断能否回指原文段落；这个主题是否会召回大量与参考文章无关的内容。不能回指或召回面过宽时继续收窄，无法收窄则不做系统深化。

## 热度记录

热度字段写“可见信号 + 采集时间”，例如：

```text
X 显示 1,240 likes、86 replies、210 reposts；采集于 2026-09-05
```

没有公开数字时写 `unknown`。博客可以记录公开评论、原作者引用、社区讨论或榜单，但不得把搜索排序换算成热度数字。

## 选题排序

先通过真实性、时效和方法密度硬门槛，再按以下维度比较：

| 维度 | 优先条件 |
|---|---|
| 受众相关性 | 直接影响 AI 工程、Agent、AI-Native 研发或用户指定方向 |
| 本周性 | 核心事件或影响发生在滚动 21 天内 |
| 方法含量 | 能拆出做法、决策、证据和边界 |
| 作者连接 | 用户有实践、判断、疑问或可以执行的验证 |
| 证据潜力 | 有可展示数字、截图、代码、日志、价格或原始案例 |
| 差异价值 | 与历史选题不是同一论点，并补充不同机制、约束或结果 |

所谓“爆款潜力”来自具体问题、真实证据、判断张力和读者可迁移价值，不来自标题炒作。

完整周报的本地编辑窗口为 21 天；X 及其关联原始文章、博客的主动发现窗口为 14 天。超过 14 天的 X 内容不能作为“新发现”入选，但可以在已有本地素材中作为背景或辅助方法论，并清楚标注。

## 单概念研究包

`topic` 模式默认选择：

- 3–5 篇核心方法论；
- 1–3 篇案例、失败、反例、成本或组织约束；
- 官方核验材料另列，不计入 5–8 篇。

`method-map.md` 只对照来源的方法、前提、证据和冲突，不替用户生成文章观点。
