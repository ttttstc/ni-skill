# Be ambitious：重新想象我们可以做到的事

帮助用户发现原先没有想到、值得尝试的新任务，并把它写成能行动、能验证的
提示词。先重构目标，再补齐专业做法；用户已限定目标时，在该范围内深化。
来源见 [README](./README.md#来源与许可)。

## 接住当前任务

任务取自 `/be-ambitious` 后面的内容。没有内容时，使用本次对话中用户最近的
请求；也没有请求时，用一句话请用户提供任务，然后停止。

沿用已有事实、材料、交付要求、硬约束、选择和授权。用户提供的文件与已授权
只读工具可以用于核查关键前提；未知项标明，不补造数字、动机、经历或工具能力。

只在缺口会改变目标取舍、主要路径或验收时追问，并说明答案会改变什么。专业
方法由你判断，不让用户替你选技术。简单任务直接给够用的改写。

## 重新设想要完成的事

把用户提出的报告、工具或 Agent 视为一种初始解法。结合其处境，判断它想促成
什么变化、当前做法卡在哪里。已有材料能支持时先给任务判断；推测的意图写成
假设。不要把所有目标归结为赚钱、提效或扩大规模。

**把名词换成动词。** 将“做一份报告”“建一个工具”还原为：让谁在什么情境下
完成什么动作、判断或决策，最终改变什么结果。保留用户指定的报告、文件和格式。
“丰富全面”“让我完全了解”还需落到具体问题和可观察效果，不能作为最终验收。

寻找最值得重新检查的前提：为什么必须采用这种产物、周期、分工或人工判断？
它来自用户的明确要求，还是旧工具、旧成本和习惯？如果有原始数据、专业工具
和及时反馈，哪些原先放弃的结果现在值得重新尝试？硬约束照守，其他前提用
材料检验，不默认成立，也不凭空宣称已经失效。

对允许探索的任务，提出能改变原解法的目标。例如从修复这次崩溃到持续保持
应用稳定；从定期汇报变成在问题发生时支持决策。也可以改变作用对象、反馈
时机和覆盖范围，或把已有材料变成原先没有的判断、预测或行动能力。

写清每个值得保留的候选：新增什么结果，替代原流程哪一步，为什么可能做成，
还依赖什么事实、工具、权限和人类判断。可以提出需要新条件的大胆目标，条件
未具备就写明缺口。不要只把人数、周期、功能堆大，或把目标换成“全面、智能、
系统化”就结束。应急与锁定范围的任务保留当前结果，不强行改造工作方式。

给出最值得追求的目标及推荐理由。有实质取舍时再列少量替代项，不机械输出
逐级升级清单。用户关心的得失由用户选择；能依据现有事实作出的专业判断由你
完成。用户已选定或授权自行选择时，直接推进，不重开选择。

## 让新目标接受专业检验

围绕推荐或选定目标，回答四个问题，将结论用于最终提示词：

1. **专家会多做什么。** 给出两三个会改变工作质量的具体动作，例如检查基础
   发生率、修复前复现、写出反方论证。按更高层结果选择动作。
2. **从什么原始材料开始。** 指出一手数据、原始文件、日志与代码、论文方法
   等具体材料；知道位置时给出入口。缺失的材料写明，不能用摘要冒充原始证据。
3. **用什么方法和工具。** 说出技术、仪器、库、命令或框架名称，以及适用原因。
   按当前任务选择专业方法，未核实的来源、工具能力和可用性明确标注。
4. **什么能独立证明结果正确。** 指定测试、复现、真值数据、测量、领域评审或
   真实用户行为，写明通过与失败条件。自我评价和表达流畅不能充当验证。

找出最影响新目标能否成立的假设：如果它成立，原始材料中应出现什么；什么
观察会推翻它？选择一个能尽快区分判断的验证动作，不用一份更长的报告代替
检验。需要现实行动才能回答的问题，写清行动、反馈入口和据此调整的方式。

大胆目标应推动新的做法与发现。可以用挑战指标暴露隐藏限制，但不能改成用户
未承诺的 SLA。说明第一次验证怎样利用现有条件开始，以及成功后能打开什么
下一步；验证失败时修正假设或方法，不只追加限制把目标退回原来的整理工作。

对新判断，用留出数据、历史回放、复现、测量或领域评审检验；合适时与原做法
比较，说明是否更早发现问题、减少了什么无效动作，或得到什么新知识。模型
赞同、独立 Agent 的文本评分及工具名称本身，均不能证明业务结果已经成立。

独立验证的数据须在形成方法前隔离。已经读过、用于选择目标或设计规则的材料，
只能用于探索或一致性检查，不能再称作独立留出。没有未用材料时，说明这一轮
能确认到哪里，提出取得新材料后的验证动作，不假装已经完成独立验证。

## 交付能接着做的提示词

只有未决选择会改变用户尚未授权的投入、承诺或关键目标时，才说明推荐与分歧，
问一个能推进选择的问题并停止。用户只要求探索选项时，交付选项即可。不要把
尚未选定的多个目标合成大项目，也不要让澄清成为固定关卡。

其余情况先用简短说明指出目标发生了什么变化，再用一个代码块交付可复制的
提示词。四问不另抄一遍，必要理由融入具体要求；只纳入当前任务需要的内容：

- 要实现的新结果、作用对象、使用情境，以及保留的交付要求；
- 能改变原做法的具体动作、原始材料、专业工具与待验证假设；
- 当前就能开始的第一步、需要返回的反馈和外部检验；
- 真实约束、通过与失败条件，以及这一轮的结束点。

保留用户口吻，删除不会改变动作或验收的修饰与重复约束。不要让解释和提示词
各写一遍相同清单。目标、方法、第一步和验证应能相互对应。

用户只要提示词时，交付后停止；已明确要求按优化后的任务执行且条件具备时，
承接已有授权开始第一步，不再询问是否开始。需要额外权限的部分再说明条件。
