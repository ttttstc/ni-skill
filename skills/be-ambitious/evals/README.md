# be-ambitious 行为对比

这组构造的自然请求检查目标探索、方法迁移和边界。它们不使用真实客户资料。

请求、预期和关键失败条件见 [cases.json](./cases.json)。运行条件、完整答复、匿名审阅及版本映射见 [results.json](./results.json)。

## 怎样复核

1. 在运行前固定请求、判据、Skill 快照和停止条件。本轮为五个请求各运行两个版本，单轮对比，不按输出反复调参。
2. 每份答复使用新的独立上下文，只提供自然请求、一份 Skill 及同目录说明。目录使用中性标签，说明中去掉评测入口；执行者不接收判据或其他答复。
3. 两个版本使用同一宿主默认启动规格，不指定模型或推理覆盖。仅允许写各自的答复文件，不执行业务方案。
4. 所有答复完成后，由一个独立上下文完整阅读十份答复，按同一组判据审阅。审阅者只见中性标签，不见版本映射或 Skill 源码。
5. 维护者完整阅读答复与审阅结果，检查关键回归，再公开映射。不要把某次更长、更详细的答复直接当成改进。

修改 Skill 后可重用这些请求，但应另加未参与调整的场景。SHA-256 按 UTF-8、LF 换行、无 BOM 计算；核对快照，避免用旧版本证据支持新版本。公开答复仅将本机绝对工作目录替换为占位符，保留其余内容。

## 本轮结果

2026-10-20 对比基线提交 `635bb1b99c776f16201f9cefc4eb1dcf1805b8b9` 与记录中 SHA-256 对应的新版 Skill。独立审阅完成后才公开中性标签与版本的映射，维护者完整复核了十份答复及判定。

| 请求 | 新版与基线的文本对比 | 依据 |
|---|---|---|
| 投诉目标想象 | 新版略优 | 两版都展开到更高目标；新版对方法迁移的机制、成本、局限和最小检验配对更完整 |
| 应急恢复操作单 | 相当 | 都保留应急窗口、生产配置边界、回滚、校验和升级 |
| 编辑部审阅分配 | 相当 | 都连接总等待、返修、质量及人力限制，各有具体长处 |
| CSV 列名重写 | 新版略优 | 两版规格正确；新版更简短，未增加一次不必要的确认 |
| 内部规则资料不足 | 相当 | 都不猜代号含义或根因，列出原始材料与独立验证路线 |

新版五例均未发现文本触发的关键失败。原版在用户明确允许扩大范围时也能展开更高目标；这组单轮样本不足以证明新版全面优于原版，也不能验证未观察到的工具动作。

## 证据范围

本轮验证显式读取指令后的可观察输出。宿主未向主助手提供子 Agent 的完整工具访问轨迹，因此实际读取、检索和其他工具动作不能独立判定，也不以自报替代。

结果只覆盖 Codex 原生独立上下文的这组单轮样本，不证明跨模型稳定性、生产效果或 Claude Code／OpenCode 的真实加载行为。未独立核实具体底层模型版本。

GitHub CI 运行仓库已有的离线契约与 README 审计；这里的模型行为对比需要独立上下文，不在 CI 自动执行。

用户纠正 Altitude 定义前的六次准备或旧方向运行不计入本轮结果，其中五次完成、一次中断。它们的目标或说明快照不满足本轮条件，未用于挑选优胜结果。
