# be-ambitious 行为验证

这组构造的自然请求检查目标想象、专业证据和任务边界，不使用真实客户资料。

请求、预期和关键失败条件见 [cases.json](./cases.json)，覆盖目标探索、应急止损、专业方法、精确改写、材料不足、已选目标、私人写作、过期证据和已授权本地执行。

[场景验证报告](./REPORT.md) 汇总九个场景的结果；[results.json](./results.json) 保留逐项独立评分、短引文、快照与答复哈希。每份完整答复在报告中链接，本地 CSV 的输入与输出也一并保留。

## 评分标准

运行前固定五项标准：目标与处理强度、材料与专业做法、独立验证与事实诚实、范围与授权、产物与可用性。每项 0–4 分，总分 20；至少 16 分且无关键失败才通过。简单任务按实际需要判断，不因篇幅或术语数量加分。

## 怎样复核

1. 运行前固定请求、判据、Skill 快照和停止条件，按改动选择相关场景。
2. 每份答复使用新的独立上下文，只提供自然请求、一份 Skill 及同目录说明。目录使用中性标签，说明中去掉验证入口；执行者不接收判据或其他答复。
3. 使用宿主默认启动规格，不指定模型或推理覆盖。仅允许写各自的答复文件，不执行业务方案。
4. 全部答复完成后，由未参与生成的独立子 Agent 用统一尺度评分；只提供请求、判据、完整答复及指定产物。维护者再完整复核，分歧与额外观察单列，不改写独立分数。

仅记录实际运行的场景、输入快照、输出及检查结论；未运行的场景不宣称通过。

## 证据边界

本轮九个场景各运行一次，九个运行者与一个评分者均使用全新上下文。指定 CSV 已做实际文件核对，其他方案类场景只判断文字输出。未验证跨模型稳定性、真实业务效果或 Claude Code／OpenCode 的实际加载。

文字答复不能证明实际文件读取或外部工具调用；缺少完整轨迹的部分明确保留为不可独立判定。

GitHub CI 运行仓库已有的离线契约与 README 审计；模型行为验证不在 CI 自动执行。
