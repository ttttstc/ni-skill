# be-ambitious 行为检查清单

这组构造的自然请求检查目标想象、专业证据和任务边界，不使用真实客户资料。

请求、预期和关键失败条件见 [cases.json](./cases.json)，覆盖目标探索、应急止损、专业方法、精确改写和材料不足。清单本身不表示行为检查已经通过。

## 怎样复核

1. 运行前固定请求、判据、Skill 快照和停止条件，按改动选择相关场景。
2. 每份答复使用新的独立上下文，只提供自然请求、一份 Skill 及同目录说明。目录使用中性标签，说明中去掉验证入口；执行者不接收判据或其他答复。
3. 使用宿主默认启动规格，不指定模型或推理覆盖。仅允许写各自的答复文件，不执行业务方案。
4. 答复完成后，按预定判据复核完整输出，检查关键失败。需要独立审阅时，只提供请求、判据与答复。

仅记录实际运行的场景、输入快照、输出及检查结论；未运行的场景不宣称通过。

## 证据边界

文字答复只能证明可观察的输出。实际文件读取、工具调用、业务执行和宿主加载需要各自的运行证据；未核实的部分明确标注。

GitHub CI 运行仓库已有的离线契约与 README 审计；模型行为验证不在 CI 自动执行。
