# CI 值班 Agent 离线验证答复

结论：**可行性尚未证实**。本轮可复现显式链关联、按证据更新卡片、按阶段提出不同的核查方向，以及保留未知；没有证据证明建议优于‘每次失败都先重试’。这不能作为上线验收。

还有一项必须披露的方法限制：初次检查时执行者已经读取完整静态 CSV，包括 10 月 7—9 日记录。后续程序在冻结规则后执行前缀回放，决策函数不接收未来运行或任何处理记录；其输入边界可以审计。但这不是执行者盲化的留出试验，无法排除规则设计受已见答案影响。任务要求先探索训练段再保留后段回放；这一次在冻结前已看过后段，因此本轮严格留出条件**未通过，本轮验证不通过**，须用另一批未用材料复验。没有发现程序决策读取未来的具体案例，不能把这个程序检查升级为全程无泄漏证明。

## 2. 冻结的规则、评判口径和关联边界

先由 freeze 命令选取 10 月 1—6 日共 17 次运行、6 个失败事件、10 个失败决策时点，写入冻结规则.json；该阶段不读处理表。随后 replay 校验冻结时的脚本 SHA-256，再产生逐时建议。冻结后未修改规则。完整文件指纹见审计.json。训练段建议是样本内逐时上下文演示，不充当独立效果评估。

事件 ID=E+显式链根 run_id。只有 rerun_of 可并入事件；相同阶段/节选的不同根只可引用历史。跨提交、未登记的成功只作弱关联候选，不改事件图。显式链出现 success 才标记‘观察到恢复’，含义仅为该链后来成功。

| 优先序 | 适用条件 | 主要下一步 | 训练依据 |
|---|---|---|---|
| R1 | 当前显式链已有失败，当前再次失败；优先于其他规则 | 停止机械重试，结合阶段核查证据并交人工判断 | 04→05；07→08；12→13；15→16 |
| R2 | 首次 fetch connection reset | 安全、幂等且无持续故障迹象时有条件尝试一次重试 | 02→03；10→11 |
| R3 | 首次 verify expected / actual 节选 | 先核查断言、输入和本提交变更，拒绝仅凭文本认定根因 | 04；05 |
| R4 | 首次 publish HTTP 403 | 先核查原始响应、有效身份、目标与策略，403 不等于权限根因 | 07；08 |
| R5 | 首次 build No space left on device | 先核查目标挂载、空间、inode 或配额，不自动清理 | 12；13 |
| R6 | 首次 verify deadline exceeded | 先核查验证步骤、实际耗时、超时配置和资源证据 | 15；16 |
| R7 | 首次 fetch deadline exceeded；训练段未出现的阶段组合 | 先核查拉取超时边界和幂等性，满足条件后才考虑一次重试 | fetch 的 02/10；verify 的 15/16；仅用于指出不能跨阶段直接迁移 |
| R8 | 未覆盖或证据不足 | 保留未知，补原始错误与定位信息并交人工判断 | 资料缺少完整日志和独立根因真值 |

R7 是冻结时写下的跨阶段迁移限制，不是从 fetch timeout 的已知结果估计概率；但执行者已见静态留出材料，仍受前述非盲限制。规则不读取处理动作；没有动作时间，连训练段的历史处置也不能假定在某次回放时已经可用。历史可引用的只有早于当次的运行观察。

评判前置：支持假设的结果是关联可追溯、不误并、阶段能改变核查对象、重跑失败后能更新、陌生错误能保留未知，且建议函数只用时间前缀。失败标准是关键词/时间误并、无依据根因诊断、因果越界、未来输入或机械重复重试。处置合理性和根因没有独立真值，统一列为待领域评审；另一个模型的赞同与 recorded_outcome 均不能替代。

主要对照固定为每次失败都先建议重试。关键词对照固定按节选给通用动作：connection reset→有条件重试；expected/actual→核查差异；403→核查响应；No space→核查容量；deadline→核查超时；未知词→交人工。它不看 phase、显式链和次数。后续观察只分‘与建议方向相容/存在张力/无法判断’，不产生自评分，也不推算生产效果。
