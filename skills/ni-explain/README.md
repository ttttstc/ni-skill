# ni-explain

中文 | [English](./README.en.md)

一份面向中文技术方案、概念讲解与业务/技术汇报的写作 Skill，支持**写、改写、审查、讲解**四种模式。目标只有一个：**让读者一次读懂，只有一种理解**。

它从 ASD-STE100（Simplified Technical English）的受控语言思路出发，针对中文技术写作的常见毛病做了适配；并在句子之上补了两层——**结构**与**载体选择**。

## 适用场景

- 技术方案、设计文档、评审材料
- 业务 / 技术汇报（只管表达层；价值判断与框架归 `ni-tech-report`）
- README、操作手册、运维 / 故障排查文档
- 把陌生概念讲给非技术读者
- 对既有文本做改写、审查、讲解

## 保持原样，不改

- 代码字面量、命令、API 路径、环境变量、字段名
- 事实、数字、日期、结论、条件、例外、边界
- 引用原文、专有名词、以及作者自己的话
- **本来就没问题的句子**（护栏 §0.4：已经清楚就不改）

## 三层清晰度

| 层 | 手段 | 参考 |
|---|---|---|
| 句子级 | 受控中文：一词一义、无万能动词、写明主体、单句 ≤50 字（步骤 ≤40 字） | `references/rules-zh.md` |
| 结构级 | 结论先行、已知→未知、一段一判断、先地图后街道 | `references/explain-patterns.md` |
| 格式级 | 文字 → 列表 / 表 → 图 → HTML → 视频脚本，按读懂难度选载体 | `references/explain-patterns.md` |

## 四种模式

| 模式 | 输入 | 产出 |
|---|---|---|
| 写 | 材料 / 提纲 | 按规则写出的清晰文本 |
| 改写 | 现成文本 | 清晰版（保事实，只改表达） |
| 审查 | 现成文本 | 问题清单，不改 |
| 讲解 | 一个概念 / 方案 | 选对格式 + 套讲解法，从零讲清楚 |

## 核心规则概览

规则全文见 [`references/rules-zh.md`](./references/rules-zh.md)，分 10 章；开头一节是**优先级最高的护栏**：

- **护栏（0）**：同一对象同一名称；条件 / 例外贴在对应动作旁；分清建议 · 要求 · 可能；**已经清楚就不改、不为简短删原因边界**
- **词 / 名词短语（1–2）**：一个概念一个词、不用含糊词、名词前最多一层修饰
- **动词（3）**：不用万能动词、写明主体（主动句）、要求只用 应 / 宜 / 可
- **句子（4）**：一句一事、写明主语、代词只指一个、单义连接词
- **步骤（5）**：一步一条、祈使句开头、条件放前面
- **说明（6）**：结论先行、一段一主题、数字带条件
- **警告（7）**：放步骤前、先指令后后果、警告 / 注意两级
- **标点长度（8）**：全角标点、中英空格、日期格式
- **写作习惯（9）**：术语一致、代码照原样、不写中文 AI 腔

## 与 ni-tech-report 的边界

`ni-tech-report` 管「判断立不立得住」（立意 / 姿态 / 证据 / 收束），`ni-explain` 管「这句话读不读得懂」。**在汇报上，ni-explain 只借句子、不碰判断**——反比喻成语、长度上限、结构重排规则一律让位于汇报的价值框架；内容层缺判断不归它管，它不做转交、不指路。

## 借鉴 STE 的技术写作方法

本 Skill 的受控中文规则借鉴 ASD-STE100 的九章思路与防误读原则：术语一致、主动语态、一步一动作、条件前置、两级警告、不为缩短而省略成分。

**但它不是 STE 的中文版，也不承诺 STE 合规**：

- STE 的核心是 Part 2 的**受控词典**（Issue 9 约 900 个批准词）；ni-explain **没有受控词典**，只有禁用词类 + 项目术语表。
- 单句长度：STE 用 20 / 25 英文词；本 Skill 用 40 / 50 中文字。STE 本身也声明字数限制不外推到其他语种。
- 机械检查结果只表示「该看的地方」，**不代表 STE 合规**。

标准背景见 [ASD-STE100 官方说明](https://www.asd-ste100.org/)。

## 快速开始

```bash
# 机械检查：报出「该看的地方」，不是判决。确定=机械可判；存疑=需判断（含误报）
python scripts/check.py 你的方案.md

# 离线自检
python tests/smoke_test.py
```

## 文件结构

```text
ni-explain/
├── SKILL.md                       # 主入口：四种模式 + 三层清晰度 + 主流程
├── references/
│   ├── rules-zh.md                # 受控中文规则（0 护栏 + 10 章）
│   ├── explain-patterns.md        # 结构层 + 格式阶梯 + 讲解法 + 压长句五手法
│   └── output-template.md         # 四种交付格式
├── scripts/check.py               # 机械检查（标准库）
├── tests/                         # smoke + 契约测试
├── evals/                         # skill-up 评测（5 用例）
└── README.md / README.en.md
```

## 评测与自检

```bash
python tests/smoke_test.py
python -m unittest tests/test_skill_contract.py
```

`evals/` 是与 skill-up 配套的评测配置（5 个用例：改写去万能动词 / 审查不改写 / 讲解选格式 / 汇报保留框架不转交 / 去套话）。
