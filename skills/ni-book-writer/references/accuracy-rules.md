# 准确性铁律（主要服务技术书种）

> 技术书的可信度命根子。畅销书守"事实不虚构"底线即可（人物/引语/事件/时间不编造），本文件主要服务技术书。

## 零猜测
每个行为断言、每个数值，必须可追溯到三者之一：① 官方文档 ② 可观测行为（能复现的事实）③ 源码。三者皆无 → **不写死结论，只描述边界**，并标"官方未公开此数值 / 此细节"。

## 不许的措辞
- **含糊词**：基本上 / 通常来说 / 某种程度上 / 一般而言 / 大概 / 可能（除非明说"在 X 条件下不确定"）。
- **标注腔 / 元话语**：官方明示 / 合理推断 / 可观测现象 / 置信度 / 本书标记为 / 我们认为——正文不暴露写作过程与判定体系。
- **无依据的绝对化**：完全一致 / 一律 / 永远——只在确有依据时用；官方说 almost identical 就写"基本一致"。

## 数值与版本
- 取值类型、默认值、上限必须给**具体值**；查不到写"官方未公开此数值"，不写"有上限 / 有默认值"了事。
- **易漂移数值**（账户配额、计费、随计划变化的限制）指向官方页、不写死。
- **锚定时点**：全书声明"行为以 <年月> 的 <平台> 为准"；行为变更记入附录编年。

## 高风险区单独审
触发逻辑、权限 / token、安全边界、各类上限——错一条就是硬伤。单独逐条过，产出"断言 → 出处"台账。

## 核实手段
优先官方文档、官方 changelog、开源源码、可复现实验。**记不清就去查，不靠记忆下结论**——记忆会骗人，尤其是具体数值和日期；具体日期类断言若查不到出处，改成模糊表述（"近期已…"）而非写死一个未经核实的日期。
