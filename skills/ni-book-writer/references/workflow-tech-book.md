# 技术书生产管线（机制拆解型）

> 从《GitHub Actions 运行机制蓝皮书》的写作工程（process/ 全套 + 写作标准 TEMPLATE v3）反推。配合 `style-tech-book.md` 使用。

## 输入模式
主题 + 官方文档 / 领域知识 → **系统化拆解**成卷-篇-章。不是改编现成素材，而是把一个领域的实现逻辑重新组织成可复刻的体系。

## 5 阶段生产管线

### 阶段 1 · Blueprint（动笔前先定）
- **定位**：与官方文档 / 同类书的分工——一张对照表，说清本书答"怎么运转 / 为什么如此 / 放弃了什么"，而非"字段是什么"。
- **读者与路径**：列 2-3 类目标读者，各给一条阅读路径；读者差异靠章首索引、速查表、案例标签满足，**不在正文里分叉写作**。
- **主线 + 分界**：锚 1 条贯穿全书的结构主线，再立 1-2 条关键分界当全书钩子。
- **大纲**：卷 → 篇 → 章三级；篇按"执行链路 / 决策链"排序，不按语法元素罗列；每篇先定一句"核心问题"。
- **术语表**：同一概念全书一个中文叫法，新术语先入表再用；专名（workflow、job、ref…）留英文不译。

### 阶段 2 · 逐章写作（八段式 + 五段定义条目）
每章按固定**八段式**（见 `structure-templates.md`），顺序不可换。每个定义条目按**五段式**：解决的问题 / 定义与语法 / 运行机制 / 设计原因（含"放弃了什么"）/ 关联与陷阱。语法示例**最小且完整**（删一行不工作、加一行多余），注释写"为什么"不写"是什么"。复杂机制加「实现机制解析」节，区分**可观测行为 / 实现取舍**，以"要维护的状态"收束。

### 阶段 3 · 准确性审稿（详见 `accuracy-rules.md`）
逐条核对每个行为断言、每个数值，对照官方文档 / 可观测事实 / 源码；三者皆无则只描述边界并标"官方未公开"。高风险区（触发逻辑、权限、安全、数值上限）单独再过一遍，产出准确性台账（断言 → 出处）。**零猜测**是这一步铁律。

### 阶段 4 · 图（详见 `figure-rules.md`）
先定全局风格基准（配色 / 线条 / 字体 / 图内文字规则），再为每张图写"逐图说明"（框内文字、连线、标注、唯一强调点），正文放占位 `![图 X-N](pic/chXX-名/fig-NN.png)` + 读图指引。时间先后 / 对比 / 多分支 / 层级四类内容必配图。占位与说明保持 1:1。

### 阶段 5 · 案例库（详见 `structure-templates.md` 案例六段）
工程案例独立成部分、按类拆文件；卷首多维索引（意图 / 事件 / 技术栈 / 安全等级）。每案六段：适用判断 / 完整配置（复制即用）/ 逐块拆解（指回原理节）/ 优秀实践与反模式 / 常见坑 / 对应原理。保证"案例 ↔ 原理"双向可跳转。

### 终审打磨
去 AI 腔（过 `ai-blacklist.md`）、重点句加粗（每节约 1）、删自夸填充与装饰比喻、统一人称"用户"（清掉"我"）、校字、查交叉引用不断链。

## 完成自查清单（第一部分每章）
- [ ] 章首有核心问题句 + 定义索引表
- [ ] 基础概念节覆盖本章全部前置概念
- [ ] 每个定义条目五段齐全（第五段可豁免）
- [ ] 时间 / 对比 / 多分支 / 层级四类内容全部有图或表
- [ ] 每个定义条目有最小完整代码示例
- [ ] 行为速查总表 + 高频疑问齐备
- [ ] 全文无 emoji、无元话语、无标注腔、无装饰比喻、无第一人称"我"
- [ ] 数值约束给具体值或明确写"官方未公开"
- [ ] 每条行为可溯源
