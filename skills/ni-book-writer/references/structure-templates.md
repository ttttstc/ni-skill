# 结构模板（卷-篇-章 / 八段式 / 定义条目五段 / 案例六段 / 传记章）

## 技术书 · 全书结构
序章 → 第一部分（概念与实现逻辑，篇按"执行链路 / 决策链"排序，可分卷）→ 第二部分（案例库，按类拆文件）→ 附录。
- 编号：篇内"N.x / N.x.y"两级；跨篇引用"详见篇 M 的 M.x"；案例"Cx-y"。禁"上文提到 / 前面说过"这类无定位指代。
- 每篇一个 md 文件 `chNN-语义名.md`；`SUMMARY.md` 维护目录与完成状态。

## 技术书 · 章八段式（顺序不可换）
```
# 篇 N　章名
【本章核心问题】一句话加粗，钉死本章解决的根本问题。
【本章定义索引】表格：定义名/关键词 → 节号。
N.1 基础概念       本章全部前置概念，每个 1-2 段从零讲起；末配概念关系图。
N.2 基础执行链路   端到端流程图 + 文字走读；先整体地图再细节。
N.3 起 定义条目    按官方语法目录顺序，每条走五段式（见下）。
（复杂机制）实现机制解析  区分 可观测行为 / 实现取舍，以"要维护的状态"收束。
倒二节 行为速查总表 本章定义 × 关键场景的汇总矩阵。
末节 高频疑问      问题口语原句 → 简短正解 → 指回节号。
（章末）范围外说明  本章不覆盖的边界一句话列出。
```

## 技术书 · 定义条目五段式
```
### N.x 定义名：一句话说明
**这个定义解决的问题**：一行加粗。
一、定义与语法   完整语法/取值/约束/默认值 + 最小可用示例（删一行不工作、加一行多余；注释写"为什么"）。
二、运行机制     配置后平台实际发生什么：判定步骤、生效时机、边界行为（边界用"条件→结果"表）。
三、设计原因     为什么这样设计、换来什么、放弃什么。官方未说明的用"官方未解释，但从 X 行为可看出 Y"。
四、场景速查     表格："我想要 X → 怎么配"，给到可直接复制。
五、关联与陷阱   与相邻定义的交互、已知坑，每条一两句 + 指向节号。（无内容可省；其余四段不可省。）
```

## 技术书 · 序章（只做四件事，不进定义细节）
① 定位声明（本书 vs 官方文档对照表 + 按定义/按场景/按问题三条查询路径）② 三类读者阅读路径表 ③ 整体架构图（层级 + 各篇位置）④ 全生命周期总时序图 + 标出贯穿全书的关键分界。语言面向最不熟悉的读者，不出现未解释术语。

## 技术书 · 案例六段（第二部分）
卷首多维索引（按意图 / 事件 / 技术栈 / 安全等级检索）。每案：
```
### Cx-y 案例名
适用场景：解决什么真实问题；不适用于什么。
完整配置：完整可运行，复制即用；占位用尖括号集中说明。
逐块拆解：按配置块顺序，每块两三句——做什么、为何这样配、指回原理节号。
优秀实践与反模式 / 常见坑 / 对应原理（指回第一部分，双向可跳转）。
```

## 技术书 · 附录
术语表（中文 — 英文 — 一句定义 — 首次节号，全书唯一权威）、行为漂移编年（倒序：日期/变更/影响节/公告链接）、FAQ 总索引、易混淆概念对比速查。

## 畅销书 · 传记章结构（无小标题）
- **章节式标题** + 开头一段**精要**（这章讲什么故事、为何重要，让外行也能进入）。
- 正文一篇流动到底：开场入戏 → 中段（时间或主题推进，转折当场景）→ 收尾余韵。
- 大节之间最多一个空行，**不设小标题、不用 bullet、不人工分节**。
- 面向印刷：无链接、无屏幕依赖元素；没接触过素材的外行可独立读懂。
- 长度由故事密度决定，不强求短。
