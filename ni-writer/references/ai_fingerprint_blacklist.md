## 二、中文化禁区清单(完整版)

按层级分类,每一类列出常见踩雷词、问题描述、替代方案。

### 内容层

#### 1. 意义膨胀句

**问题:** AI 喜欢给任何事物贴上"重要时刻""历史性转折"的标签,把日常事件膨胀成文明叙事。

**踩雷词:**
- 标志着……的重要时刻 / 转折点
- 见证了……的演进
- 折射出更宏大的……
- 为……奠定了基础
- 开启了……的新纪元
- 在……史上具有里程碑意义
- 翻开了……的新篇章
- 凝聚了……的智慧结晶

**替代方案:** 直接陈述事实,删除评价性膨胀。

```
× GPT-4 的发布标志着 AI 发展史上一个重要的转折点。
✓ GPT-4 在 2023 年 3 月发布,首次在多项基准测试上接近人类水平。
```

#### 2. 公式化"挑战与未来"段

**问题:** AI 写文章习惯在结尾加一段"尽管面临挑战,但前景光明",这种段落毫无信息量。

**踩雷模板:**
- "尽管面临 X、Y、Z 等挑战,但凭借……,依然蓬勃发展"
- "面对未来,我们需要……"
- "随着技术的不断进步,这一领域将……"
- "在新的形势下,我们应该……"

**替代方案:** 删除整段,或换成具体的下一步预测(带数据和时间)。

#### 3. 模糊归因

**问题:** AI 用"业内人士""有专家"做权威背书,但说不出具体是谁。

**踩雷词:**
- 业内人士指出 / 业内人士分析认为
- 观察人士认为
- 有专家表示 / 据专家分析
- 相关报道称
- 业界普遍认为
- 据悉
- 有消息人士透露
- 一项研究表明(不给出处)

**替代方案:** 给出具体的人、机构、时间、出处。如果没有具体来源,删除整句或改写为"我观察到"。

```
× 业内人士认为,服务网格在中等规模团队里收益有限。
✓ 这是我在过去两年帮 4 个团队评估服务网格引入决策后得到的判断。
✓ Linkerd 创始人 William Morgan 在 2023 年的访谈中也提到过这一点。
```

#### 4. 促销腔

**问题:** AI 写到地名、产品、组织时会自动切换到旅游手册式的赞美腔。

**踩雷词:**
- 蓬勃发展 / 欣欣向荣 / 如火如荼
- 熠熠生辉 / 璀璨夺目
- 底蕴深厚 / 源远流长
- 座落于 / 位于风景秀丽的
- 享誉海内外 / 备受瞩目
- 引领潮流 / 走在前列
- 一流的 / 顶尖的 / 卓越的
- 独具匠心 / 别具一格

**替代方案:** 删除所有评价性形容词,只留事实陈述。

#### 5. 空泛积极结尾

**问题:** AI 喜欢用一段励志感的话结尾,即使前文是冷静分析。

**踩雷句式:**
- 未来可期
- 让我们一起拥抱 / 迎接 / 见证……
- 星辰大海
- 道阻且长,行则将至
- 未来已来,只是分布不均
- 在……的浪潮中,我们将……

**替代方案:** 用具体的、可验证的下一步陈述结尾,或用结尾七种(引用 / 哲思余韵 / 行动呼吁 / 信念宣言 / 回环呼应 / 眩晕收束 / 实操级总结)中的任一种代替。

### 语言层

#### 6. AI 高频中文词(收紧版)

**问题:** 这一批词在 2023 年之后被 AI 大量使用,频率远超人类自然写作。

**全禁:**
- 赋能 / 赋能于
- 心智 / 心智模型
- 抓手 / 颗粒度
- 拉通 / 对齐
- 闭环 / 链路
- 范式 / 范式转移
- 增长飞轮 / 第二曲线
- 解构 / 重构(作为动词被滥用时)
- 端到端 / 一站式

**严格降频(全文不超过 1 处,且必须有具体语境支撑):**
- 生态 / 维度 / 纵深
- 底座 / 底层逻辑
- 复盘 / 治理
- 护城河

**替代方案:** 直接换成具体的动词或名词。

```
× 这个工具能赋能开发者的工作流。
✓ 这个工具能帮开发者每天少做 30 分钟重复工作。

× 我们需要拉通各团队达成对齐。
✓ 我们需要让三个团队的负责人坐下来商量一下。

× 这是一个端到端的解决方案。
✓ 这套工具从代码提交一直管到生产部署。
```

#### 7. 学究腔副词(全禁)

**问题:** AI 喜欢用看似深刻的副词,实际是空话。

**全禁:**
- 本质上 / 究其本质
- 归根结底 / 究其根源
- 从根本上 / 从根源上
- 不言而喻 / 毋庸置疑 / 显而易见
- 不可否认 / 无可争辩
- 说白了
- 客观上 / 主观上(在不必要的位置)

**替代方案:** 直接删除,陈述句往往不需要这些副词修饰。

```
× 本质上,这是一个组织问题。
✓ 这是一个组织问题。

× 不可否认,AI 编码工具已经改变了开发方式。
✓ AI 编码工具已经改变了开发方式。
```

#### 8. 预告与公告(全禁)

**问题:** AI 习惯在做事之前先宣告自己要做事,这是 chatbot 的肌肉记忆,放到长文里就成了水分。

**全禁:**
- 接下来让我们 / 下面来看
- 首先我们要知道 / 我们先来看
- 值得一提的是 / 值得注意的是
- 需要指出的是 / 必须强调的是
- 让我们深入探讨 / 让我们一起来看
- 废话不多说 / 闲话少说
- 在深入讨论之前,我们需要先了解

**替代方案:** 直接进入正题。

```
× 接下来让我们看看半自动化卡点的衰退机制。
✓ 半自动化卡点的衰退路径相当稳定。
```

#### 9. 负向排比与尾随否定

**问题:** "不仅 X,更是 Y" "不只是 X,而是 Y" 这种句式 AI 痕迹极重。

**踩雷句式:**
- 不仅 X,更是 Y
- 不只是 X,而是 Y
- 与其说是 X,不如说是 Y
- 不是 X 的问题,是 Y 的问题(滥用版)
- X,而非 Y(刻意对仗)

**收紧规则:** 全篇最多 1 处,且必须有真实的对位关系,不能为了对仗而对仗。

```
× 这不仅是一次架构升级,更是一次组织变革。(AI 标志句)
✓ 这次架构升级表面上是技术问题,实际上要解决的是团队协作模式问题。
```

#### 10. 系动词回避(全禁)

**问题:** AI 倾向用复杂构造替代简单的"是""有"。

**全禁:**
- 扮演着……的角色
- 承担着……的使命
- 体现了……的精神
- 彰显出……的特质
- 蕴含着……的智慧
- 凝聚了……的力量

**替代方案:** 直接用"是""有""做"。

```
× Sidecar 扮演着流量代理的角色,承担着治理逻辑下沉的使命。
✓ Sidecar 是流量代理,负责治理逻辑。
```

#### 11. 浅层 -ing 中文版(全禁)

**问题:** AI 用"……着""为……提供了支撑"这种句尾来制造虚假深度。

**全禁:**
- 体现着 / 彰显着 / 反映着 / 折射着
- 为……提供了支撑 / 注入了活力 / 奠定了基础
- 推动着 / 引领着(作为修饰短语)
- 标志着……的(已并入意义膨胀句)

**替代方案:** 改写为具体动作。

```
× 这套设计体现着我们对可靠性的追求,为业务稳定运行提供了支撑。
✓ 这套设计在过去 18 个月里把核心接口的 P99 稳定在 50ms 以下。
```

#### 12. 同义词循环强迫症

**问题:** AI 有反复用代码,会在相邻三句话里把同一主体换三个同义词。

**禁规则:** 相邻三句话里同一主体最多换 1 次说法。允许用代词,或直接重复原词。

```
× 这家公司在 2018 年成立。该企业的核心业务是云服务。这一组织目前有员工 500 人。
✓ 这家公司在 2018 年成立,核心业务是云服务,目前有员工 500 人。
```

#### 13. 过度对冲

**问题:** AI 在不确定时会叠加多个对冲词。

**踩雷句式:**
- 可能或许也许
- 在某种程度上
- 不排除……的可能性
- 通常情况下,大体上
- 一般而言,通常来说

**收紧规则:** 一个对冲词够了。

```
× 这套方法在某种程度上可能或许也许会带来一定的改善。
✓ 这套方法可能改善这个问题。
✓ 这套方法在我观察到的 3 个团队里改善了这个问题,在其他场景没验证。
```

#### 14. 假范围(全禁)

**问题:** AI 用 "从 X 到 Y" 构造,但 X 和 Y 不在真实的尺度上。

**踩雷句式:**
- 从微观到宏观
- 从理论到实践
- 从输入到输出(没具体说什么输入输出)
- 从 A 到 Z(罗列性的)

**替代方案:** 如果 X 和 Y 真的在一个尺度上,保留;否则删除并改成具体列表。

```
× 这本书涵盖从大爆炸的奇点到宇宙网,从恒星生死到暗物质之舞。(AI 假范围)
✓ 这本书讲了三件事:大爆炸、恒星演化、暗物质理论。
```

#### 15. 被动语态与无主句(降频)

**问题:** AI 喜欢用被动语态隐藏主体。

**踩雷句式:**
- 无需配置文件
- 结果会被自动保存
- 系统将……
- 数据将被处理

**收紧规则:** 主动语态优先。被动语态只在主体确实不重要或不明时使用。

```
× 配置将被自动应用,结果会被保存到本地。
✓ 系统会自动应用配置,把结果保存到本地。
```

### 风格层(格式)

#### 16. 机械加粗(约束放宽,公众号视觉优先)

**问题:** AI 在每段都加粗几个零散关键词,让文章像 PPT。但完全禁用或严格限制加粗也不行——公众号长文文字量大,纯文字读者抓不到重点。所以这条规则不是「禁用加粗」,而是「公众号视觉优先 + 机械加粗硬禁 + 加粗密度上限」三合一。

**必须加粗的位置:**

- 所有 `##`、`###`、`####` 等各层级 markdown 标题
- 非标题格式的「伪标题」——承担「这一段讲什么」功能的引导词、分隔标记、小节名(例:「**第一种,Git Hook 触发。**」「**写在最后**」)
- 数字编号或 bullet 清单里每条的开头标识词,后面解释内容不加粗(例:「1. **第一步,统计服务数量**。具体做法是……」「- **第 1-2 周**,审批人认真审查每次告警」)
- 每段的重点句(段尾结论句或段首论点句)
- 首次定义的核心概念
- 行动锚点

**合规加粗(放宽,允许):**

以下场景下,加粗孤立关键词或词组不算机械,反而是必要的视觉锚点:

1. 首次定义核心概念——「这就叫 **上下文债**」
2. 对比并列的几个关键维度——「评估时看 **频次**、**可逆性**、**上下文依赖性** 三条」
3. 行动清单里的动作词——「**统计** 故障次数,**估算** 排查时长」
4. 专有名词、工具名、技术概念第一次出现——「**Sidecar 代理** 是核心,**控制平面** 负责策略下发」

**机械加粗(仍然禁,这是 AI 指纹):**

1. 每段都加粗 3-5 个零散词——视觉拥堵,失去重点
2. 同一个术语反复加粗——首次定义之后再次出现不再加粗,「每次都加」就是装饰
3. 加粗形容词、副词、纯强调——「**真正** 的关键」「**非常** 重要」「**显著** 提升」
4. 加粗后失去独立信息价值——抽出加粗部分单独读,如果没构成判断、动作、定义或对比维度,就是机械

**密度硬约束:**

**单段加粗字数不超过该段总字数的 15%。**

100 字段落加粗总长不超过 15 字,大约一句短句或两三个关键词。超过 15% 说明这段没真重点——什么都加粗等于什么都不是。

**正反例:**

```
× 这件事的关键是**速度**和**质量**。(机械,纯强调形容词)
× 在**评估**新工具时,要看**性能**、**成本**、**风险**、**收益**、**实施难度**。(机械,零散词高亮过多)
× **Sidecar** 通过 **iptables** 拦截流量,**控制平面** 下发配置给 **Sidecar**,**Sidecar** 执行 **策略**。(同一术语反复加粗)

✓ 但还有另一种债是看不见的。**那就是上下文债。**(合规,概念定义)
✓ 评估时主要看 **频次**、**可逆性**、**上下文依赖性** 三条。(合规,并列维度)
✓ **第一版只要存在,后面每次 PR 就会有人补一行、改一行。**(合规,段尾判断)
✓ **今天就做的事:在 repo 根目录 touch AGENTS.md。**(合规,行动锚点)
```

**判定方法:** 三步走。第一步,数密度——加粗字数除以段落总字数,超过 15% 必改。第二步,抽内容——把加粗部分抽出来单独读,如果不是判断、动作、定义、并列维度,必改。第三步,看重复——同一术语在文章里加粗超过 1 次,后续出现去掉加粗。

#### 17. 内联标题列表(全禁)

**问题:** AI 喜欢用 "- **标题**:内容" 这种格式排版,像 PPT。

**禁:**
```
- **性能**:有了显著提升
- **安全**:得到了加强
- **可用性**:大幅改善
```

**替代:** 改写为散文段落,或改成纯文字的数字列表。

#### 18. emoji 装饰(全禁)

**问题:** AI 在标题或 bullet 前加 🚀💡✅ 装饰。

**禁:** 一律不用 emoji,无论在标题、bullet、强调位置。

#### 19. Title Case 中文版(全禁)

**问题:** 英文环境下 AI 会把标题里每个单词首字母大写。中文环境的对应版本是把标题做成对仗工整的四字结构。

**禁:**
- "技术突破 创新引领"
- "深耕实践 砥砺前行"
- "破局之道 制胜之钥"

**替代:** 标题用自然中文短语,不刻意对仗。

#### 20. 弯引号(全禁)

**问题:** ChatGPT 默认输出弯引号("…")而非直引号或中文「」。

**禁:** 不用 "" 和 ''。中文环境用「」或直接不加引号。

#### 21. 三段排比强迫症(收紧规则)

**问题:** AI 强行把任何东西塞进三的列表。

**收紧规则:** 三联排比全篇不超过 2 处,且每次使用必须有真实的三元结构,不能为了排比而排比。

```
× 这次活动有主题演讲、圆桌讨论、网络交流。参与者将获得创新、灵感、行业洞察。(AI 双重三段)
✓ 这次活动有几场演讲和讨论。中间留了时间给大家自由交流。
```

#### 22. 标题下重复标题的废话(全禁)

**问题:** AI 喜欢在小标题下面加一句空话,然后才进入正文。

**禁:**
```
## 性能
速度很重要。
当用户遇到慢的页面,他们会离开。
```

**替代:**
```
## 性能
当用户遇到慢的页面,他们会离开。
```

### 沟通层

#### 23. Chatbot 协作残留(全禁)

**问题:** Chatbot 式的客套话被复制粘贴到文章里。

**禁:**
- 希望对你有帮助
- 当然!
- 你说得完全正确!
- 如果需要更多信息,请告诉我
- 这是一个……
- 让我来为你介绍

**替代:** 直接进入正文。

#### 24. 知识截止免责(全禁)

**禁:**
- 据我所知截至 XXXX 年
- 根据现有资料
- 虽然具体细节有限
- 在我训练数据之内

**替代:** 直接陈述。如果真的不确定,改写为"我没查到准确数字,但根据我的经验,大致是……"。

#### 25. 谄媚口吻(全禁)

**禁:**
- 好问题!
- 您说得非常好
- 完全正确
- 这是一个非常深刻的观察

**替代:** 删除。

### 填充层

#### 26. 填充短语(全部精简)

| 踩雷 | 替代 |
|------|------|
| 为了达成这一目标 | 为了达成这件事 |
| 由于它正在下雨的事实 | 因为下雨 |
| 在这个时间点 | 现在 |
| 在你需要帮助的情况下 | 如果你需要帮助 |
| 系统具有处理 X 的能力 | 系统能处理 X |
| 重要的是要注意,数据显示 | 数据显示 |

#### 27. 权威感套话(全禁)

**问题:** AI 用这些短语假装在揭示更深的真相,但后面跟的内容往往只是把普通观点用更隆重的方式重述。

**禁:**
- 真正的问题是
- 归根结底 / 究其根本
- 关键在于 / 核心在于
- 深层次的问题是
- 问题的本质是
- 现实是
- 重要的是要明白

**替代:** 直接说。

```
× 真正的问题是,团队是否能适应。归根结底,关键在于组织准备度。
✓ 问题是团队能不能适应。这主要看组织愿不愿意改变习惯。
```

#### 28. 复合连字符词组(英文环境问题,中文环境对应版本)

**英文问题:** AI 习惯把常见词组用连字符连起来:cross-functional、data-driven、high-quality、real-time。

**中文对应问题:** AI 习惯用"X 化 + Y 化"或"X 性 + Y 性"叠加。

**禁:**
- 数据化、可视化、智能化、标准化(连用 3 个以上)
- 系统性、全面性、整体性、长期性(连用 3 个以上)
- 高质量、高效率、高水平(连用 3 个以上)

**替代:** 选最关键的一个保留,其他删掉。

## 四、每类禁区的替代心法

清单很长,但底层只有四条心法:

### 心法 1:能砍则砍

副词、修饰语、对冲词、强调词,删完后句子还成立,就删。

### 心法 2:抽象换具体

模糊的形容词换具体数字,模糊的归因换具体来源,模糊的"很多""一些"换具体范围。

### 心法 3:被动换主动

"被实现""被推动""被赋能"全部改成"谁做了什么"。

### 心法 4:废话直接进入

所有"接下来""让我们""值得注意的是"删掉,直接进入正题。

掌握这四条心法,清单里 90% 的禁区可以靠直觉规避。剩下 10% 是那些"AI 标志性句式"(比如"不仅 X 更是 Y""扮演着 X 角色"),需要专门记忆。
