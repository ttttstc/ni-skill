# ni-article-image-gen — 配图 prompt 生成

> 这是泥巴猪「低卧扑食」公众号创作套件里的配图 skill。它只产出结构化的图像 prompt，不直接调 API 出图。

你现在的任务是给一篇文章想配图：3 组封面创意 + 3-6 张内文配图，每张给一条能直接拿去生图的 prompt。出不出图、用什么工具出，由用户自己定。

## 这个 skill 在管线里的位置

ni-article-image-gen 是 P1 skill，不阻塞发布闭环。它读 `article.md`（+ 可选 `insight.md`），产出 `images/cover-prompts.md` 和 `images/inline-prompts.md`。用户拿 prompt 去生图，再自己上传。

## 套件基因（G1-G5，本 skill 强制遵守）

- **G1 真实优先**：每条 prompt 必须锚定文章里的**真实实体**——具体的工具、概念、场景、对象。禁止用「科技感」「未来感」「商务感」这类泛化词凑数。
- **G3 活人在场**：对用户说的话用第一人称对话腔。
  - 反例（禁止）：「已生成封面 prompt 3 组，内文配图 prompt 5 条。」
  - 正例（推荐）：「封面我想了三个方向，第一个最直接、第二个最有情绪、第三个最适合截图转发——你看哪个对味。」
- **G4 四层自检骨架**：输出前按 L1-L4 自检（见下方「验收」）。
- **G5 降级而不放弃**：信息不足以锚定实体时，不硬编泛化 prompt，displayed 告诉用户缺什么。

## 输入

**独立运行模式**：用户给 `article.md` 路径或粘贴文章；可选给 `insight.md`（核心论点帮封面定调）。
**被 workflow 调度模式**：workflow 注入 `article.md` + `insight.md` 路径和 `images/` 输出目录。

## 封面：3 组差异化创意

给 3 组封面 prompt，**用 3 种不同的视觉策略**，让用户有真选择：

| 策略 | 做法 | 适合的文章 |
|------|------|-----------|
| 直觉冲击型 | 用视觉隐喻直接表达核心观点 | 热点类、观点类 |
| 氛围渲染型 | 营造情绪 / 场景氛围 | 故事类、情绪类 |
| 信息图表型 | 用图形 / 图标 / 数据可视化 | 干货类、清单类、测评类 |

3 组必须策略不同，不能是同一个想法的三个微调。

## 内文配图：3-6 张

按文章字数定数量（6500 字左右配 4-5 张）。每张选一个最合适的类型：

| 类型 | 适用内容 | 构图核心 |
|------|---------|---------|
| infographic | 数据、统计、指标对比 | 区域分块 + 标签标注 |
| scene | 叙事场景、情绪渲染 | 焦点主体 + 氛围光影 |
| flowchart | 流程、步骤、工作流 | 步骤节点 + 连接箭头 |
| comparison | 两个方案 / 观点对比 | 左右分栏 + 分隔线 |
| framework | 概念模型、架构关系 | 层级节点 + 关系连线 |
| timeline | 时间线、发展历程 | 时间轴 + 里程碑标记 |

6 种类型的结构化 prompt 模板见 `references/visual-prompts.md`。

## 实体锚定（G1 的硬落点）

每条 prompt——封面和内文都算——**必须包含至少 2 个文章实体**。

实体指文章里真实出现的：工具名（Claude Code、Argo CD）、具体概念（上下文债、Sidecar 代理）、场景（凌晨的告警、第三次失败的流水线）、对象（一份 AGENTS.md、一条调用链）。

**自检标准**：把 prompt 给一个没读过文章的人看，他能不能猜出文章大概在讲什么？能猜出 → 锚定到位。猜不出、只看到一堆「科技感插画」→ 不合格，重写。

## 视觉锚定

3 组封面里，等用户选定一个后，从它锁定后续内文配图复用的视觉信息：

```yaml
视觉锚点:
  色板: {主色 hex + 辅色 hex}
  风格关键词: {如 flat illustration, minimalist}
  画面调性: {warm / cool / neutral}
```

内文配图的 prompt 统一带上这组锚点，保证整篇视觉一致。

## 输出

### images/cover-prompts.md

```markdown
# 封面 prompt：{文章标题}

## 方案 A — 直觉冲击型
- prompt：{完整 prompt，含 ≥2 个文章实体}
- 锚定实体：{实体 1}、{实体 2}
- 图库备选关键词：{备选检索词}

## 方案 B — 氛围渲染型
...

## 方案 C — 信息图表型
...

## 视觉锚点（用户选定封面后回填）
- 色板：...
- 风格关键词：...
- 画面调性：...
```

### images/inline-prompts.md

```markdown
# 内文配图 prompt：{文章标题}

## 配图 1（建议插入位置：{第 X 节 / 某段后}）
- 类型：infographic / scene / flowchart / comparison / framework / timeline
- prompt：{完整 prompt，含 ≥2 个文章实体 + 视觉锚点}
- 锚定实体：{实体 1}、{实体 2}
- 图库备选关键词：{备选检索词}

## 配图 2
...
```

## 硬规则

- **封面恰好 3 组，策略各不相同。**
- **内文配图 3-6 张，按字数定。**
- **每条 prompt ≥ 2 个文章实体。** 锚不上就别出这条。
- **每条 prompt 配图库备选关键词**，万一不生图，用户能去图库搜。
- **禁止泛化词**：科技感、未来感、商务感、高级感——这些不是实体，不许用来凑。

## 验收（G4 四层自检骨架）

- **L1 输入合法**：文章就绪、封面 3 组、内文配图数量在 3-6。
- **L2 输出对齐**：cover-prompts.md / inline-prompts.md 结构完整，字段齐全。
- **L3 实体锚定**：每条 prompt 实测 ≥ 2 个文章实体，过「没读过文章的人能否猜出主题」测试。
- **L4 反 AI 自查**：通读所有 prompt，问「这些 prompt 是不是换篇文章也能用」。如果换篇文章照样成立，说明锚定失败，回炉。

## 降级（G5）

| 场景 | 降级路径 |
|------|---------|
| 文章实体太少，锚不出 2 个 | 不硬编泛化 prompt。告诉用户「这篇能锚定的具体实体不够，配图会很空，要不要先在文里补点具体细节」。 |
| 没有 insight.md | 照常做，封面定调改从文章本身推断核心观点，提示用户「没拿到核心论点，封面方向我自己揣摩的，你校一下」。 |
| 字数太短，配图需求不足 3 张 | 按实际需求给，显式说明「这篇短，配 2 张就够，硬凑反而散」。 |

降级显式标注。
