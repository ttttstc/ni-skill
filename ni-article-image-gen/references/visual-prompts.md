# 配图 prompt 模板库

> 本文是 ni-article-image-gen 的模板参考。风格**默认黏土定格动画**，用户也可指定其他风格。本文给：默认风格块、为其他风格写风格块的结构、6 种构图类型模板、封面写法、9 张内文分布、实体锚定正反例。

---

## 1. 风格块

每条 prompt——封面和 9 张内文——都要附一个**完整风格块**。整篇文章 10 条 prompt 共用同一个风格块，不混风格。

### 1.1 默认风格块：黏土定格动画

用户没指定风格时，用这一段。原样附上，不能只写「黏土风格」四个字带过——模型要靠这些细节才能稳定出定格动画感，而不是普通卡通插画。

```
【风格：黏土定格动画 / claymation stop-motion】
所有元素都是手工黏土（橡皮泥 / plasticine）捏成的实体模型，不是平面插画，不是 3D 渲染。
- 材质：黏土表面有清晰的指纹、捏塑工具划痕、略微不平整的哑光质感，能看出是手捏的。
- 场景：一个微缩实景搭景（tabletop miniature set / diorama），物件有真实的体积和重量感。
- 灯光：柔和的影棚灯光，暖调，有真实的投影、轮廓光和浅景深。
- 触感：手作的、温暖的、略带不完美的质感，参考 Aardman 定格动画（《超级无敌掌门狗》）的体积感和憨拙感。
- 人物：用简化的黏土小人表现，靠姿态、动作和身体语言传递情绪，不做写实面孔。
- 镜头：略带俯视或平视的实拍感，像在拍一个真实存在的微缩模型。
```

### 1.2 切换到其他风格

用户指定了别的风格（水彩、扁平插画、像素风、胶片感、版画、针管笔手绘……），就为那个风格写一个**等价的完整风格块**。结构照搬下面五项，把内容换成目标风格：

```
【风格：{风格名}】
{一句话定位：这是什么媒介 / 什么质感}
- 材质：{表面质感、笔触 / 颗粒 / 纹理特征}
- 场景：{画面是平面的还是有空间、背景怎么处理}
- 灯光：{光影特征，或「平涂无光影」}
- 触感：{整体气质，温暖 / 冷静 / 锐利 / 怀旧……}
- 参考：{一个明确的视觉参照，让模型有锚点}
```

写得越具体，出图越稳。模糊的「好看的风格」不算风格块——遇到模糊指定，按 SKILL.md 的 G5 降级，问用户要具体方向。

## 2. prompt 通用结构

每条 prompt 由四部分拼成：

```
{风格块：默认黏土，或用户指定的}
+
{构图描述：这张图画什么、怎么摆}
+
{文章实体：至少 2 个文章里真实出现的工具/概念/场景}
+
{色板：全文统一的 2-3 色色板}
```

四部分缺一不可。风格块和色板全文统一，构图和实体每张不同。

---

## 3. 色板

每篇文章定一组 2-3 色色板，10 条 prompt 共用。

- 按文章气质选：技术冷静题材偏雾蓝 + 奶油白；踩坑 / 警示题材偏砖红 + 赭土；轻松分享题材偏暖橙 + 苔绿。
- 黏土风默认从橡皮泥常见色里挑（赭土色、奶油白、暖橙、苔绿、雾蓝、砖红、奶咖色）；其他风格按该风格的调性挑。
- 每个颜色给一个 hex，方便生图工具对齐。
- 选定后写进 `cover-prompts.md` 开头。

## 4. 封面写法（3 构思方向，产 1 张）

封面只产 1 条 prompt。先判断走哪个构思方向，再用当前风格落地。下面例子用默认黏土风演示，换风格时构图思路不变、只换风格块。

### 直觉冲击

用一个场景视觉化核心观点。

- 例（文章讲「AI 不是替你写得更快，是替你不写不该写的代码」，黏土风）：
  > 一只手停在键盘上方没有落下，屏幕上一段代码正在被轻轻按掉，画面克制、留白多。

### 氛围渲染

把文章里最有画面感的真实场景表现出来。

- 例（文章开头是凌晨流水线第三次失败，黏土风）：
  > 一个微缩工位，深夜，一块小屏幕亮着红色失败日志，房间其余部分隐在暖色暗光里，安静而紧绷。

### 结构具象

把文章核心结构（几条标准 / 几个步骤）做成一组小物件。

- 例（文章是「评估工具看三条标准」，黏土风）：
  > 三个小牌子并排摆在桌上，分别表现使用频次、配置成本、回滚难度的小图标，像一组手作展品。

封面 prompt = 选定方向的构图 + 风格块 + ≥2 实体 + 色板。

## 5. 9 张内文配图分布

9 张要铺满全文，按位置走：

| # | 位置 | 常用构图类型 |
|---|------|------------|
| 1 | 开头场景 / 钩子 | scene |
| 2-3 | 第一个主要章节 / 第一个核心论点 | scene / framework |
| 4-5 | 中间章节、机制或对比 | comparison / flowchart / infographic |
| 6-7 | 核心判断、数据、关键论证 | infographic / framework |
| 8 | 落地路径 / 步骤 | flowchart / timeline |
| 9 | 结尾收束画面 | scene |

这是默认骨架，不是死规定——按文章实际章节调整。原则是：**每个主要章节至少 1 张、每个核心判断配 1 张、开头结尾各 1 张**。

## 6. 6 种构图类型模板

构图类型只管「画面里有什么、怎么摆」，与风格无关——任何风格下都套用。风格由风格块负责。模板里的 `{风格块}` 换成第 1 节选定的那一段。

### scene — 叙事 / 情绪

```
一个表现 {文章里的真实场景} 的画面，焦点是 {主体实体}，氛围烘托 {情绪}。
+ 风格块 + 色板
```

### infographic — 数据 / 指标

```
一张信息图，展示 {文章里的具体数据/指标}，区域分块，每块带标签写着 {实体/数字}。
+ 风格块 + 色板
```

### flowchart — 流程 / 步骤

```
一张流程图，从 {起点实体} 到 {终点实体}，中间是 {文章里的步骤节点}，用箭头连接。
+ 风格块 + 色板
```

### comparison — 对比

```
一张对比图，画面左右分栏，左边 {方案A实体}，右边 {方案B实体}，中间一道分隔线。
+ 风格块 + 色板
```

### framework — 概念模型 / 架构

```
一张层级结构图，每个节点是一个 {概念实体}，节点之间用连线表示 {实体1 与 实体2 的关系}。
+ 风格块 + 色板
```

### timeline — 时间线

```
一条时间轴，沿线排列代表 {文章里关键事件} 的里程碑，从 {起始时间点} 到 {结束时间点}。
+ 风格块 + 色板
```

> 黏土风下，这些构图会自然带上黏土质感（节点是黏土块、箭头是黏土搓的）——这一步由风格块负责，模板本身不写死「黏土」二字，方便换风格时复用。

## 7. 实体锚定正反例

**反例（泛化，禁止）**：
> 一个科技感的场景，展现 AI 与未来，蓝色调。

问题：「科技感」「AI 与未来」不是文章实体，换任何 AI 文章都能用 = 锚定失败。风格词也顶不了实体。

**正例（锚定到位，黏土风）**：
> 一份摊开的 AGENTS.md 文件摆在桌上，旁边一个小人代表 Claude Code 正低头读它。
> + 黏土定格动画风格块 + 暖橙/奶油白色板

为什么合格：「AGENTS.md」「Claude Code」是文章真实实体，没读过文章的人也能猜出这篇在讲 AI 协作规范；风格、色板齐全。

**自检**：把 prompt 给没读过文章的人，他能猜出文章主题 → 过；只看到「一些小物件」→ 回炉。

---

## 8. 两个不能省的检查

写完每条 prompt，过两关：

1. **实体关**：数一数，文章实体够不够 2 个？风格词（「黏土」「水彩」）不算。
2. **风格关**：风格块附了没？是不是完整的那一整段五项结构，而不是风格名几个字？10 条 prompt 是不是同一个风格块？少了或不一致，整套图就散了。
